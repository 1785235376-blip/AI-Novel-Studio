# V0.5.2 Phase 1 Lore Context Integration Report

## Result

V0.5.2 Phase 1 is implemented. Approved, active character memory can now be added to Writer context through an opt-in Lore Context extension. The default remains disabled, so the V0.4.8 Context Pack shape and values remain unchanged.

## Implementation

- Added `LoreMemoryView` with `short_memory`, `medium_memory`, `long_memory`, `evidence_summary`, and `memory_version`.
- Added the internal `ContextEnvelope` containing base context, Lore memory, retrieval reasons, privacy decisions, and token budget.
- Added targeted retrieval from the characters already selected by the base context. The implementation calls per-character active-memory queries and does not load all novel memories.
- Added chapter validity-range filtering and optional volume/novel snapshot retrieval.
- Added evidence summaries and a conservative cloud privacy boundary:
  - memory backed by `LOCAL_ONLY` evidence is omitted from cloud context;
  - evidence excerpts are not emitted to cloud context;
  - unclassified derived snapshots are omitted from cloud context.
- Added `ENABLE_LORE_CONTEXT=false` to Settings and `.env.example`.
- Extended `ContextService` without changing its disabled/default output.
- Added an Agent context adapter rule: only the Writer Agent receives `lore_memory`; other existing agents retain their previous context.
- Connected Lore repositories to the existing Context Service composition roots.

## Compatibility Rules

- `ENABLE_LORE_CONTEXT=false`: exact legacy base Context Pack is returned; no `lore_memory` key is added.
- `ENABLE_LORE_CONTEXT=true`: `lore_memory` is appended as an optional extension.
- Only `ACTIVE` Character Memory is retrieved. PENDING or REJECTED proposals are never queried as Writer memory.
- Existing fields are not removed or renamed.
- No Context Pack serialization, repository protocol, migration, API, or frontend contract was changed.

## Known Limits

- Retrieval is deterministic and relational; vector search and embeddings are intentionally not implemented.
- Phase 1 exposes Character Memory plus existing volume/novel snapshots. Dedicated location, event, and arc memory entities do not yet exist and are therefore not synthesized.
- Snapshot privacy has no per-item classification in the current schema, so snapshots are conservatively excluded from cloud requests.
- Pytest reported a local `.pytest_cache` write-permission warning; test execution and assertions were unaffected.

## Deferred

- Lore UI
- Vector or embedding retrieval
- Automatic plot planning
- Automatic proposal approval or Canon mutation
