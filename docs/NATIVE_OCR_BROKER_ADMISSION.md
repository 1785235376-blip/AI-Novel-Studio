# Private native OCR admission in the original broker

2026-10-18. **Real original-broker hooks now execute with the native OCR worker in
File and PostgreSQL checks. Public Research preview/dispatch/review remain unwired.**

A trusted-only LOCAL_NATIVE_OCR_ONLY_V1 candidate profile inventories exact
LocalTesseractOCRProvider instances through the original registries and
VisionOCRModelNode. It checks pinned native binding and executable availability,
rejects subclasses/declarations/disabled models, and fingerprints provider identity.
It never appears in the default candidate inventory or accepts a client-supplied
candidate_profile field. The existing generic VISION real-adapter refusal remains.
Native selection cannot become TEXT, cloud fallback, synthetic execution, a chapter
request or a different narrative task.

The existing broker preview/reserve/guard_dispatch/finalize owners are reused.
Native provider-invoice cost is known zero, explicitly excluding host compute;
its state is KNOWN_LOCAL_PROVIDER_ZERO, never KNOWN_SYNTHETIC_ZERO. No new wallet,
invoice engine, scheduler, provider registry or budget owner is introduced.

Private native previews and ledger rows carry the original project incarnation.
Reservation keys include it. Old native rows remain unchanged in the original
store but do not consume the new incarnation's holds or appear in its native views.
An original owner lease is required for private-native admission and settlement.
Generic reconciliation refuses private native rows pending an owner-aware recovery
flow. This filtering is limited to newly stamped private-native rows: it is not a
migration or full isolation audit of legacy broker metadata or budget configuration.
