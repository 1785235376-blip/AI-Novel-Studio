## 3. Implementation

- Added a persistent, namespace-isolated `ConflictDialog` resolution flow with local/server comparison, manual resolution editing, explicit server discard, focus containment, Escape restoration and live status regions.
- Added persistent conflict-resolution drafts and repeated-conflict history without overwriting prior records.
- Recovery keys combine full workspace/project/storyline/branch scope with an opaque session fingerprint, preventing another actor/session in the same browser profile from hydrating unpublished recovery data.
- Integrated manual resolution with the existing optimistic save path using the latest server version as `baseVersion`; successful commit clears the scoped recovery record, while a second 409 preserves the new draft.
- Fixed scoped server-version cleanup to pass the active namespace, preventing stale conflict recovery from reappearing after refresh.
- Added `RevisionPanel` with typed timeline/detail contracts, human-readable historical/current comparison, explicit two-step restore confirmation, expected-version restore, loading/empty/error/unauthorized states and persistent restore-conflict feedback.
- Integrated RevisionPanel into the existing NOVEL workspace without changing AppShell, ModuleSwitcher, ContextBar, tokens or protected surfaces.

## 4. Conflict Safety

- Local content is persisted before save and remains available after a 409.
- Resolution commits use the current server version as `expected_version` through the existing save API.
- Repeated conflicts preserve the newer resolution draft and do not silently overwrite it.
- Same-user and different-user stale writes remain protected by backend CAS and authorization.
- No force-overwrite path was added.

## 5. Revision / Restore

- Revision history remains immutable and restore is append-as-new-current.
- Restore requires explicit confirmation and sends the current chapter version.
- A restore 409 or authorization failure preserves the preview and reports the failure without reload-driven silent loss.
