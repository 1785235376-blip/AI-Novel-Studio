## Security contract

- The launcher bootstrap secret uses `secrets.token_urlsafe(48)`, exists only in process memory, is transferred once, expires within a configured maximum of five minutes, and is consumed atomically before session registration.
- The secret is bound to the Phase 2 `runtime_instance_id` and an exact `http://127.0.0.1:<port>` Origin.
- The exchange endpoint is POST-only and accepts only `bootstrap_secret` and `runtime_instance_id`; Pydantic rejects extra identity or authorization fields.
- The client address must be exactly `127.0.0.1`. Loopback is an additional transport restriction, never an authentication substitute.
- The response is `no-store`, `no-cache`, and `no-referrer`; the bootstrap endpoint, secret, and runtime identity are absent from frontend source and browser persistence paths.
- Secrets and session tokens are absent from safe runtime metadata, filesystem writes, log event payloads, URLs, configuration, and backup contracts.
- Packaged runtime rejects development-session JSON and requires the trusted collaboration authorization boundary. There is no development-token fallback.
- Packaged and collaboration modes both activate the existing fail-closed route boundary. Only the exact packaged bootstrap POST is newly admitted.
- Registry configuration requires the manager Origin to equal the configured frontend CORS Origin.
- Runtime invalidation revokes every token issued by that runtime; stale secrets fail with both old and new runtime identities.
