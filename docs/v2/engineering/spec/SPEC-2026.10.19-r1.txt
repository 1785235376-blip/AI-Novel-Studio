> **本文件记录的是新增及整合后的目标范围，不是完成报告。** 这里的“必须完成”不等于代码已经实现、测试已经通过或产品已经可以发布。旧版 V1.X/RC1 的冻结事实、原有质量门禁、未关闭的缺口和失败证据均不得被覆盖。

## 0. 一页决策摘要

**发布决策：**撤销此前“先发布 V2，再把 12 项增强分配到 V2.1、V2.2、V3”的建议。现在采用单一的 **V2 Release Gate**：原 V2 正式版完整范围 + 本文 12 项差异化能力 + Image Studio 漫画子功能 + 安全、兼容、性能和完整验收，全部关闭后才允许正式发布。开发过程中可以内部构建和阶段冻结，但不可把未通过的阶段包称为 V2 正式版。

**模块决策：**保留当前一级功能架构，不增加独立的 Comic Studio 顶层主模块。漫画相关入口固定为：**Image Studio → 漫画制作（Comic）**。漫画可以拥有内部编辑器、页面、分镜排版、工具面板和工作流；底层必须沿用当前项目/资产/Graph/任务/审核/权限/模型等权威体系。

**差异化定位：**重点不是“接入更多模型”，而是将故事事实、人物状态、素材版本、镜头和成片建立可追踪的跨媒介语义依赖，让作者在修改故事后可定位影响、局部重做、验证来源与质量。

**开发模式：**先完成各项的工程闭环与阶段测试，最后在同一候选版本上完成系统级实机验收。阶段测试不能替代正式验收；也不能以延后正式验收为理由长期积累未验证代码。

## 1. 产品结构与不可突破的边界

### 1.1 现有主功能保持不变

保留原 Master Roadmap 中的小说/文本、剧本、导演、分镜、图像、视频、音频、时间线剪辑、资产、模型中心、工作流/Graph、交付及其他既有系统的模块边界和现有实现归属。本文 12 项新增能力通过原模块的子页面、侧栏、命令、共享服务和受控关系索引实现；不得人为把它们拆成 12 个新的一级产品入口。

**明确的漫画导航：**

```text
PoemSeed Studio
└─ Image Studio（现有主模块）
   ├─ 图像生成 / 编辑（现有）
   ├─ 参考图 / 角色 / 风格 / 批处理（既有或待补）
   └─ 漫画制作 Comic（本次新增的 Image 子功能）
      ├─ 漫画项目 / 章节 / 页面管理
      ├─ 分页、分格与连续条漫编辑
      ├─ 漫画图像生成与局部重绘
      ├─ 对白、气泡、拟声字与文字层
      ├─ 角色一致性、风格、跨页审校
      └─ 漫画导出 / 动态漫转接
```

独立创作漫画时，允许从空白漫画项目开始，不要求先创建小说或剧本；但该漫画项目仍隶属于原 Studio 项目范围，并使用原资产和版本体系。“独立创作入口”不等于“新增一级主模块”。

### 1.2 必须复用的原有权威体系

- **项目与权限：**原 Studio project / scope / incarnation / actor / session；任何跨项目访问、旧项目 ID 复用、权限撤销之后的迟到回执都必须安全拒绝。
- **创作事实：**现有 World、Character、Story、Creative Document、Shot 等各自原有的权威源；新 Story Kernel 只能增加可核验关联、时间状态及衍生视图，不能制造第二份相互冲突的“正史数据库”。
- **任务与生成：**原 WorkflowRun、MediaJob、Asset、Model Center、Provider Registry 与审核流；漫画生成是 Image Job 的新任务类型/受控工作流，不创建平行的作业队列。
- **资产与修订：**原 Asset 身份、版本、来源引用、摘要、历史、审核状态、CAS 冲突处理、撤销与恢复机制；漫画页、分格与气泡建立从属记录而非绕过 Asset 审核。
- **时间线：**漫画转动态漫时调用既有 Video/Audio/Timeline 入口，不另建视频渲染引擎。
- **公开版隔离：**保留现有公开版/内部研究版的产品、数据、模型及后端策略隔离要求。新增漫画入口不得成为绕过原版内容安全与授权策略的特殊通道。

### 1.3 需求编号与证据状态

本补充规范使用 `DIF-01…DIF-12` 表示 12 项差异化增强，`IMAGE-COMIC-01…20` 表示漫画子功能条目；这两组是 **产品需求 ID**，不是声称已有的 API ID、数据库表名或仓库实现路径。

每条需求应分别标注：`PLANNED`（仅需求）、`IMPLEMENTED`（有代码）、`INTEGRATION_VERIFIED`（有真实调用/集成证据）、`ACCEPTED`（满足正式验收）或 `BLOCKED`（依赖未解决）。如发现旧系统存在可复用部分，必须给出源码位置和本轮验收证据；不因名字相同就标为已完成。

## 2. 十二项差异化能力：全部为正式 V2 发布必做

### DIF-01｜Story Kernel：跨媒介故事世界内核

**目标：**把小说、剧本、漫画、分镜和影片共享的角色、地点、事件、因果、时间和知识边界转为结构化、可追溯的叙事事实视图。

**MUST：**支持角色身份与别名、事件时间区间、地点与道具状态、角色当时已知/未知事实、事件因果链、来源版本、事实冲突与作者裁决；同一事实跨媒介复用；既有正文和世界设定继续为权威输入；支持分支世界与不同剧情版本的隔离。AI 推测必须与作者确认的事实区别显示。

**不可偷换：**不能把“RAG 检索到相关段落”当作已建立事实关系，也不能让世界模拟器悄悄重写作者批准的剧情。

**验收：**给定多章节故事，录入角色秘密、物品毁损和时间线变更；小说、剧本、漫画、分镜引用一致；在事件发生前错误使用后续状态时发出可定位警告；无权跨项目读取事实被拒绝；关闭模型后仍能读取/手改事实。

### DIF-02｜Impact Engine：叙事变更影响分析

**目标：**作者改动剧情事实、人物外观、镜头或模型参数后，在执行任何再生成之前，显示受影响对象和原因。

**MUST：**跨 `Text → Screenplay → Comic/Storyboard → Image → Video/Audio → Timeline/Export` 建立源版本关系；展示直接与间接影响、影响范围、可保留资产、重做建议和预计资源代价；可选择仅更新部分依赖；记录分析依据及作者决定；不自动改写被批准资产。

**不可偷换：**已有的文件版本号、父资产 DAG 并不等价于完整的跨媒介“语义影响分析”。

**验收：**修改一条“角色后续应出现的伤痕”设定，能够列出相关漫画格、剧本镜头与视频；未受影响资产指纹不变；循环依赖、过期源或缺失证据返回明确阻塞原因，不虚构完整性。

### DIF-03｜Identity Studio：人物与场景身份连续性

**目标：**将角色的剧情身份、视觉身份、声音身份及随剧情变化的外观状态绑定到统一资产与时间点。

**MUST：**支持角色参考集、版本化立绘、表情/姿态、服装与道具状态、固定视觉特征、配音特征、场景参考、跨镜头/跨漫画格一致性检查；允许主动创建“新服装版本”而非一律判错；绑定生成模型实际支持的参考能力；差异检测提供比较图和人工确认入口。

**验收：**同一角色生成 8 个漫画格、3 个分镜和 2 个视频镜头；正确复用批准的身份参考；换装时间点前后状态不混淆；角色脸部偏差、丢失道具等可被标记复核；未知或模型不支持的控制方式如实显示。

### DIF-04｜Semantic Rebuild：跨媒介局部重制

**目标：**将“修一处内容，不重做整部作品”变为受控产品能力。

**MUST：**基于已批准源版本、运行配方、输入摘要和依赖图生成重制计划；区别“仅需重新排版”“局部修图”“必须重生单格/单镜头”“仅需重新导出”；执行前显示将覆盖的草稿和会保留的正式版本；支持人工审批、候选对比、回滚、取消后核实和未知状态恢复；无权云端调用不得偷偷发生。

**验收：**漫画页只改一个对白气泡时不触发图像生成；修改单格背景时其余格保持字节或来源版本不变；修改影响跨镜头道具时给出多对象重制清单；网络中断后不重复付费执行未知任务。

### DIF-05｜Scene Twin：三维场景与镜头数字孪生

**目标：**为漫画和视频提供共用的 3D 场景布局、角色站位、相机与空间关系参考。

**MUST：**支持模型/场景/相机的有类型资产与版本；为 Blender/UE5 建立至少一条真实可运行、可回读或有损说明的交换链；明确坐标系、单位、骨架/材质支持范围；可从 3D 场景导出镜头构图图像、深度/姿态/遮罩等受支持的参考；不把截图导入冒充完整三维互通。

**验收：**真实 3D 文件和一组相机关键帧往返验证坐标/方向；一个镜头修改站位后，漫画/分镜参考更新但原素材不被覆盖；不支持的格式或材质属性生成损失清单。

### DIF-06｜Performance Director：表演导演

**目标：**让作者不仅描述“人物很悲伤”，还能控制可执行的表演细节。

**MUST：**支持镜头级视线、表情、动作节奏、手势、肢体朝向、对白停顿、台词情绪、声画时间点和镜头节拍；区分导演意图、参考输入和模型最终输出；对不支持姿态/口型/动作控制的模型提供诚实降级或换模型建议；可对一个镜头局部修改后继续审查。

**验收：**一段双人对话在漫画、分镜及短片中具有同一情绪转折；修改停顿时间只影响需要重排的音视频任务；不会声称普通文本提示词就实现了精确骨骼控制。

### DIF-07｜Studio QA：跨模态质量与一致性审校

**目标：**创建人机协作的审校机制，而不是虚构一个“AI 评分即通过”的认证器。

**MUST：**确定性检查（缺页、错序、断链、超出气泡、缺失字幕、无效来源、帧率/音量/分辨率异常）与模型判断（人设一致性、表演情绪、故事节奏、画风偏差）分开呈现；提供证据定位、置信与限制、修复建议、作者忽略/确认与复审历史；不能由 AI QA 自行批准正式资产。

**验收：**故意构造错时台词、漫画阅读顺序颠倒、视频缺帧、对白溢出、音量突变，系统能定位并生成可操作提示；主观意见只标注建议而不自动定罪。

### DIF-08｜Model Lab：模型对比、实测与智能调度

**目标：**把选择模型从“看名字猜性能”变为有证据的任务适配。

**MUST：**支持不同模型在相同受控任务上比较质量、耗时、显存峰值、实际 API 费用、输出尺寸与功能限制；记录真实测量和估算的区别；适配原 Model Center / Provider / WorkflowRun；本地模型与云端模型须分别授权；显存预算与排队/卸载策略覆盖 8GB、12GB、16GB 档位。

**验收：**同一人物漫画格可进行双模型 A/B、复用固定参考与种子（模型支持时）；实测与估算不混淆；模型中断、显存不足或远端拒绝时任务进入可恢复状态；CPU-only 模式可正常管理非推理工作。

### DIF-09｜Style DNA：多模态风格规范

**目标：**将“作品风格”从一句泛化提示词提升为可管理、可覆盖的规范集合。

**MUST：**储存写作语气、镜头语言、构图、用色、线稿/网点、人物设计、声音与音乐主题；区分全局风格、章节/场景风格和单格/单镜头覆盖；风格版本变更可交给 Impact Engine 分析；支持导入合法的参考资产与版权提示，不承诺对指定作者风格的一键精确复制。

**验收：**同一个作品在小说、漫画、分镜和视频中复用同一视觉主题；局部改变漫画页风格不改动其他批准页；相冲突的层级规则在执行前可见。

### DIF-10｜Storyverse：多分支互动叙事输出

**目标：**同一作品可形成小说正篇、漫画支线与交互式叙事分支，而不是散落的独立副本。

**MUST：**保存分支条件、选择后果、角色状态、回跳/收束点、来源和版本；可视化分支引用已批准世界事实；能够导出一种通用结构化交互包，以及经实际验证的 Ren'Py / Ink 目标适配器；不支持的语义提供显式有损转换报告；不绕过原分支权限。

**验收：**用带条件选择的短故事生成互动脚本，在目标运行环境中能正确走完主要分支；编辑一条世界规则能够检测受影响分支；不会将条件丢失却显示“完整导出”。

### DIF-11｜Audience Lab：读者/观众模拟审阅

**目标：**为作者提供来自多种阅读目标的结构化反馈，辅助发现理解难点与节奏问题。

**MUST：**读者角色由显式参数定义（题材经验、目标年龄层、阅读速度、语言习惯等）；分析须引用具体段落/页/镜头与版本；显示不同读者建议存在分歧；允许人工采纳或驳回；不将模型输出称为真实用户测试、市场数据或成功率预测；处理敏感正文须遵守既有隐私与云端授权门禁。

**验收：**同一漫画章节得到“新手阅读”和“长期读者”两份可追踪反馈；不同版本结果不混用；离线时无模型仍可查看过去审核记录，不擅自上传作品。

### DIF-12｜Production Passport：素材出处与制作过程档案

**目标：**让每份可交付作品都能说明重要素材、生成步骤、许可声明、版本和人工修改的来源。

**MUST：**导出机器可读与人类可读的来源报告；关联项目、模型/Provider、输入资产、人工/模型操作、许可声明、审批记录和导出摘要；证据缺失不得填造；允许按隐私策略隐藏敏感绝对路径/秘钥；对支持的媒体格式提供经真实验证的 C2PA 凭证生成或明确的 sidecar 退化方案。

**验收：**从成片追溯到漫画原格、原参考图与剧情章节；改动批准版后旧凭证不会被当作新文件证明；验证合法签名和被篡改文件的差异；明确“出处可追踪≠已完成法律版权认证”。

## 3. Image Studio 新增子功能：漫画制作 Comic

### 3.1 产品定义与适用场景

**模块名称：**`Image Studio / 漫画制作（Comic）`，内部需求统一采用 `IMAGE-COMIC-*` 前缀。漫画既能作为独立的图像创作项目，也能承接小说/剧本/导演/分镜的已批准内容；生成结果可以再送往视频/音频/剪辑，制作动态漫画。

**支持的主要形态（MUST）：**黑白日漫/灰度、彩色页漫、四格/短篇、连续滚动漫画（Webtoon/条漫），允许按预设选择左右/右左阅读方向。功能不是“在图片上自动写几句对白”，而是一个拥有可编辑页面结构、图层、分格、文字和版本历史的专业图像子工作流。

### 3.2 二十项漫画子功能验收清单（全部 MUST）

**IMAGE-COMIC-01｜子入口与独立项目。**在 Image Studio 内创建空白漫画、从现有文稿创建漫画、导入已有图片续做。漫画工程隶属于原 Studio 项目与 Asset，不需要小说/章节先行；新建不自动生成付费素材。

**IMAGE-COMIC-02｜漫画工程层级。**提供漫画册/章节/页面/分格/图层/气泡的结构化树与编号，支持调整顺序、复制、拆分、合并、删除恢复、快照和冲突提示；已审核旧版本不可被静默覆盖。

**IMAGE-COMIC-03｜智能分集与分格策划。**从作者提供的小说、剧本、分镜或大纲生成“章节 → 页面 → 分格”的分镜提案，包含叙事目的、画面主体、构图、人物动作、对话映射与来源片段；用户可以逐条接受或手改。

**IMAGE-COMIC-04｜专业分格排版画布。**手动/模板生成四格、网格、不规则格、跨页和长条格；可拖动格线、裁切蒙版、间距、出血、页面安全区、分格阅读顺序；页面可以有空格、无图格和纯文字格。

**IMAGE-COMIC-05｜逐格图像生成与批处理。**根据格的 Story/Identity/Style/Shot 条件形成结构化任务，支持 T2I、I2I、指定参考、批量候选、并排对比、选择批准；失败只影响对应格，禁止批处理将未审核候选自动升级为正式页。

**IMAGE-COMIC-06｜角色与服装跨页一致性。**引用 Identity Studio 的人物版本、表情、服装、道具和时间状态；跨格生成支持正反面/不同角度参考，允许剧情中的明确变装和伤痕变化，不把一切差异都误报成错误。

**IMAGE-COMIC-07｜构图、姿态与空间控制。**可将分镜框、角色站位、姿态/深度/3D 白模、镜头焦段意图等作为显式参考；仅对模型真实支持的姿态/Control/参考能力开通相应参数，其他模型显示降级路线。

**IMAGE-COMIC-08｜局部重绘与图层化修稿。**作者可手工选区、蒙版、擦除、修补、扩图、换背景和局部生成；每次重绘创建候选并保留原版本；保护对白、气泡、边框与未选择的其他格。

**IMAGE-COMIC-09｜可编辑气泡与对白文字。**气泡是独立矢量/结构化对象，支持轮廓、尾巴、位置、阅读顺序、嵌字、字号、字距、行距、对齐、横/竖排和换行；改对白不必重新生成背景图。

**IMAGE-COMIC-10｜拟声字与漫画特效。**支持拟声文字、动态线、速度线、集中线、冲击线、网点、黑白高反差、灰阶和可调图层混合；原始线稿和彩色稿分层处理，不能破坏原画不可逆地叠字。

**IMAGE-COMIC-11｜线稿与上色流程。**提供线稿清理、背景去除、局部分区上色、灰阶/网点化、色彩版与黑白版分支；可手动修画、保留编辑来源，导出前有色彩和像素边界预览。

**IMAGE-COMIC-12｜跨格/跨页连贯性检查。**关联 Story Kernel、Identity Studio 和 Studio QA；检查人物消失/重复、服装时间状态、道具位置、对白先后、格序、视线/场景轴线、跨页衔接；提示必须含具体页格位置与可验证依据。

**IMAGE-COMIC-13｜页漫与条漫双编辑模式。**支持传统分页阅读和纵向滚动编辑；能够把同一分格序列排为多页或长条图，阅读顺序人工可改；转换时显示裁切与对白溢出风险，不承诺无损自动换版。

**IMAGE-COMIC-14｜篇章节奏与翻页设计。**提供页数/格数/阅读顺序、对话密度、关键揭示镜头与翻页节点的审阅视图；AI 可提出节奏修改建议，但不得自动改变作者批准的剧情。

**IMAGE-COMIC-15｜可编辑图层与交换格式。**页面包含画面、分格、气泡文字、拟声字、遮罩、特效与注释等逻辑图层；支持保存/重开完整编辑状态，并提供实际可验证的 OpenRaster（ORA）分层交换，兼容限制和图层效果损失必须报告。

**IMAGE-COMIC-16｜翻译与多语言排字。**支持中文、英文、日文等文字层编辑及横竖排，使用字体回退；可生成翻译候选，但气泡内文本与阅读顺序由人确认；AI 翻译不得直接替换批准译文。

**IMAGE-COMIC-17｜智能局部重排与重制。**联动 Impact Engine / Semantic Rebuild：仅改对白时重排文字层，仅改特定格时局部重绘或重生该格；对跨页影响预览后再执行，不刷新不相关页面和人工修饰。

**IMAGE-COMIC-18｜漫画导出与印刷基础。**至少支持分页 PNG/JPEG/WebP、连续长图、CBZ、PDF、EPUB 3.3 固定版式，以及附带编辑工程的项目归档；支持尺寸、DPI、出血与安全区、阅读方向、元信息、打包验证；不得将未验证的 PDF/X 印刷合规声称为已支持。

**IMAGE-COMIC-19｜漫画到动态漫转接。**批准的格/页可显式转为镜头卡、镜头停留、运镜建议、对白语音和音效候选，经原 Video/Audio/Timeline 管线生成动态漫画；漫画原资产仍保持可编辑与可追溯。

**IMAGE-COMIC-20｜漫画专用协作审稿 Agent。**在同一原 Agent/任务体系中提供可选的“分格策划、漫画画面、文字排版、一致性审校、印前审稿”角色，输出可编辑建议、原始来源和审核记录；不能让 Agent 越权写入或绕过人工确认。

### 3.3 漫画子功能的用户操作流程

**流程 A：小说 → 漫画。**选择小说的已保存章节和版本 → 生成页/格提案 → 人工确认阅读顺序与台词 → 绑定角色/风格参考 → 逐格或批量生成 → 气泡/线稿/特效编辑 → 漫画 QA → 批准 → CBZ/PDF/EPUB/图片交付。

**流程 B：零文本起步。**Image Studio 新建漫画 → 选择模板/尺寸/阅读方向 → 手动画格或导入图片 → 编辑图层和文字 → 审查 → 导出。无模型、无 API 的环境也必须可完成这一流程。

**流程 C：漫画 → 动态漫。**选择已批准漫画页/格 → 按格序创建镜头建议 → 分配停留时间/镜头运动 → 配音与音效 → 交由既有时间线剪辑 → 渲染/审核/导出；任意失败不得改写漫画原稿。

**流程 D：单格返工。**定位页格 → 修改动作或背景 → 在原版本上创建候选 → 对比前后 → 通过 Story/Identity/QA 检查 → 仅批准和更新该格，生成受影响下游列表；撤回或失败时旧正式版保持可用。

### 3.4 漫画工程的数据契约建议（规划，非当前仓库 API）

需要有界且版本化的内部记录，例如：`comic_document_id`、`project_scope`、`chapter_id`、`page_id`、`panel_id`、`reading_order`、`panel_geometry`、`balloons[]`、`layer_refs[]`、`source_snapshot`、`asset_ref`、`identity_version`、`style_version`、`review_state`、`version`、`digest`。字段均需由工程人员与现有 owners 映射后确定，不能按本建议直接重复创建第二套 project 或 Asset 主表。

关键约束：页面的视觉合成是派生结果，不应取代可编辑源；图像生成回执与人工排版编辑分开存储；每个批准的格和页都可以追溯来源；项目撤权或切换后，迟到的图像/文件读取不能污染当前工程；跨项目素材复用必须通过现有授权资产引用。

### 3.5 图片格式、软件互通与诚实边界

- **ORA：**作为漫画分层交换的发布目标；必须对真实文件进行导出—导入—再编辑测试。ORA 不保证完全覆盖第三方软件的所有图层效果，所以需附差异说明。
- **CBZ：**由按阅读顺序排序的页面图像构成，附合理元信息与校验清单；需在至少两种独立阅读器或一款阅读器加独立解包工具中验证排序与图像完好。
- **EPUB：**以 EPUB 3.3 固定版式为正式目标，必须使用实际阅读软件验证分页与方向。EPUB 3.4 的 Roll 模式尚不宜作为广泛兼容性的发布保证；条漫正式输出优先长图/分段图片。
- **图层文本：**编辑器内部必须保留真实可编辑的气泡与文本属性。导出为 PNG/PDF 时可栅格化合成，但不应把栅格输出冒充编辑源。
- **艺术资源：**参考图、字体、纹理、模型的使用许可留存于 Asset/Passport；不提供未经授权抓取、复制受保护作品的捷径。

## 6. 正式发布硬门禁与测试场景

### 6.1 V2 Release Gate：任何一项未关就不得发布

1. **完整范围：**原 V2 Master Roadmap 内所有发布必需条目关闭；`DIF-01…12` 逐项为 `ACCEPTED`；`IMAGE-COMIC-01…20` 逐项为 `ACCEPTED`，不得用“功能演示录屏”替代交互验收。
2. **无新顶层模块：**漫画必须保留在 Image Studio 内，启动导航、权限、项目和生产关系均通过原系统；不能出现需要另开一个 Comic App 才能完成的必需流程。
3. **真实用户任务闭环：**小说→剧本→漫画/分镜→图像/视频/声音→时间线→导出；以及“从空白漫画开始→编辑→出图→交付”两条路径都真实可操作。
4. **核心正确性：**版本/CAS、跨项目权限、来源摘要、人工审核、重试幂等、未知状态恢复、删除/撤权及恢复在真实后端和前端交互中通过；不能静默覆盖已批准素材。
5. **本地和云端：**无模型时仍可编辑/浏览/导出既有素材；已配置本地模型可运行实际任务；云端运行先遵守授权与费用确认。支持的 Provider 必须有实际可复现证据，不以 Mock 代替真实模型。
6. **漫画成品质量与可编辑性：**至少通过“独立黑白页漫”“小说改编彩漫”“长条漫画”“单格返工”“动态漫转接”五类样例；文本层可再次修改，导出文件能被独立软件打开。
7. **跨软件互通：**受承诺支持的 3D、时间线、漫画工程及导出格式均实际导入/导出并校验；有损处可定位、有报告，不能标注为无损。
8. **性能与资源：**完成 8GB/12GB/16GB 显存档位的能力门槛、实际监测和安全退化；大漫画工程分页/缩略图缓存可控，失败不得无限增长占用；输入、输出、缓存、临时和测试文件有明确配额与清理策略。
9. **平台与安装：**真实 Windows 11 首次安装、升级、卸载/保留数据、重启恢复、路径迁移、输入法、模型检查、WebView/桌面宿主、清洁环境复测完整记录；CI 红色不能被解释成通过。
10. **安全和授权：**公开版/内部研究版隔离、模型上传授权、资产许可、敏感信息脱敏、临时文件清理与可追溯性通过；C2PA 声明边界正确；不因漫画新增而扩大自动外传范围。
11. **验收归档：**机器可读状态矩阵、样例工程、原始日志、操作截图/视频、构建 SHA、环境版本、失败记录与修复关联均可核查；所有状态使用真实证据。
12. **发布授权：**全部门禁通过后，由原授权流程决定正式公开发布。未通过时只能是开发快照/内部 RC，不打 V2 正式标签，不发布宣称完整的安装包。

### 6.3 测试证据分层

## 7. 工作纪律、变更控制与交付格式

1. **不破坏旧成果。**保留 V1.X 冻结、RC1、原 Interop、开放 PR 和既有通过/失败日志。代码变更在目标分支上追加，先看最新远端 HEAD，不做 reset/force push。
2. **已做过的不重做。**开发助手须对每个 `DIF`/`IMAGE-COMIC` 需求建立“原有可复用/新代码/验收缺口/证明链接”四列表，而不是凭记忆重写功能。
3. **不扩建主模块。**漫画必须位于 Image Studio 内；新增功能优先采用子面板和共享能力，不能为了命名漂亮再造数据库与队列。
4. **阶段冻结不等于正式发布。**开发中应持续运行必要的快速回归，并逐阶段归档；最终全部做完后再进行完整实机系统验收和统一发布判定。
5. **区分事实与计划。**每份报告注明源代码 SHA、测试范围、`PASS/PARTIAL/BLOCKED/NOT_RUN`、实际模型/机器和失败原因，不编造进度百分比。
6. **可持续离线使用。**无 AI 时仍应能创作、编辑、检查已有数据、保存和导出；支付 API、在线账号和自动下载安装不能是基础编辑器的硬依赖。
7. **测试数据与磁盘容量。**大规模模型和媒体测试使用隔离目录和明确配额；生成的可再生临时测试产物在验收留证后安全清理，禁止误删正式用户工程和测试证据清单。
8. **验收责任。**任何 AI 自动检查的内容均以证据为准，真实模型质量和最后用户可用性必须经过人类审阅；出现不可验证环节按 BLOCKED/LOCAL_REQUIRED 报告。
