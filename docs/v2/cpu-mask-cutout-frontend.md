# Standalone CPU binary-mask cutout surface

The original independent IMAGE workspace's **制作操作 → 媒体制作与审核** panel accepts `m5.image.cutout`. It keeps the existing AppShell, shared controls, production client, receipt controller, Asset collection and workspace mutation semaphore.

## Explicit flow

1. Select one current PNG source.
2. Select one saved authored binary mask pinned to that source's exact ID, version and digest.
3. Read and confirm the production preview.
4. Create the original image job in QUEUED state.
5. Explicitly execute it.
6. Read the private PNG candidate and verify its actual digest and exact byte count.
7. Explicitly confirm review and promote through the original review endpoint.

No provider, model, prompt, cloud permission or tunable processing parameter is part of this operation. The source snapshots are ordered `[source, authored mask]`. Input parameters are `{}`. Response-only `reference_only: true` metadata does not change those exact bindings.

Mask eligibility is an advisory projection from the original Asset owner's `manual_mask` receipt and verified, non-stale MANUAL_EDIT provenance. Imported lookalikes and masks painted for another source revision do not become eligible. The backend still verifies actual source/mask bytes and authority at its original execution boundaries.

Changing source or mask versions, digests, availability or provenance revokes preview/review consent and private browser URLs. Selecting current source versions explicitly clears the prior mask binding; the user must select a matching mask again.

## Local execution and recovery

The recipe decoder accepts only LOCAL_CPU_MASK, PNG_RGBA8_STORED_DEFLATE, WHITE_KEEP_BLACK_TRANSPARENT_ZERO and no fallback. Source dimensions are 64–1024, in multiples of eight. Processing proofs bind both source digests and the output digest. Output bytes must match the deterministic stored-DEFLATE formula and the 4,195,716-byte maximum.

Same-page control during synchronous execution is a narrow exception inside the existing workspace mutation owner. It allows one original-job GET or GET-then-CAS cancellation for that exact executing cutout. The global mutation lock remains held until execution and any control request have both settled. Imports, navigation and unrelated mutations remain blocked.

Cancellation reads the current original version before sending its CAS. Duplicate clicks do not repeat the request. Lost or conflicting control responses remain uncertain until an explicit original-job read. Late execution responses cannot overwrite verified cancellation or clear uncertain control state. Identity loss during the control read prevents the cancellation POST and redacts late results.

UNKNOWN and REVIEWING expose explicit reconciliation. A CANCELLED job with a processing proof but no attached private candidate can reconcile that original publication evidence while remaining CANCELLED. Cancellation never enables review or regeneration.

## Graph remains closed

Graph operation types, selector labels, parameter maps and receipt command types retain the original nine-operation set. Graph cannot acquire cutout from widening the standalone MediaOperation union. The read-only cutout advisory descriptor rejects Graph action paths; it is not execution authority.

## Verification and limits

- 73 additive tests: 52 strict DTO/eligibility/catalog cases and 21 mounted original-workspace cases.
- The decoder regression includes unchanged public DTO projections generated by the synthetic mounted backend API test. These fixtures contain no user data, credentials, private paths or runtime logs.
- Mounted cases cover explicit stages, stale source/mask consent, lost-create recovery, private candidate verification, Host/project/session/actor/branch ABA, nested-control ABA, duplicate cancellation, CAS conflict recovery, semaphore retention and late-response fences.
- TypeScript, production build, the UI token guard and unchanged focused original regressions pass.
- Final full frontend regression: 305 passing files, 2,814 passing tests, 8 unchanged existing skips. No original assertions or skip markers were changed.

Browser-native PNG decoding, real-browser visual/geometry screenshots and Windows end-to-end acceptance remain unverified because browser execution is blocked in this environment. No sandbox bypass was attempted. jsdom tests verify control flow and real PNG hash/size checks; they do not certify native image display. Product acceptance remains LOCAL_REQUIRED.

No actual network generation, models, user Windows environment, push or upload was used for this slice.
