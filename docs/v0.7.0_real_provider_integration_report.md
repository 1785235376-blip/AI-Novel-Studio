## Runtime Error Model

The compatible adapter maps:

```text
401/403 -> AUTHENTICATION_FAILED / 模型凭据无效
429     -> RATE_LIMITED / 请求过于频繁
404     -> MODEL_NOT_FOUND / 找不到所选模型
400/422 -> INVALID_REQUEST / 生成请求无效
5xx     -> PROVIDER_UNAVAILABLE / 模型暂时不可用
timeout -> TIMEOUT / 生成超时
network -> PROVIDER_UNAVAILABLE / 模型暂时不可用
cancel  -> CANCELLED / 已停止生成
```

Raw response bodies, `Authorization` headers, exception objects and API keys do not enter safe messages or metadata.

## Streaming, Cancellation and Timeout Contracts

`OpenAICompatibleTextProvider` owns an `httpx` streaming response, parses SSE through decoded lines rather than assuming TCP-chunk boundaries, ignores non-data/blank frames, recognizes `[DONE]`, normalizes deltas and emits a final response with finish reason and usage when supplied.

Cancellation is propagated from the Job event through the request to the adapter. Pre-start cancellation opens no request. Active-stream cancellation exits the read loop and the owned response context closes the stream. The Job consumes `generation.cancelled` and cannot subsequently transition to completed or mutate the manuscript automatically. Partial text remains preview-only.

Timeout policy implemented:

```text
connect timeout = 10 seconds
first response/read timeout = 30 seconds
overall generation timeout = 120 seconds
```

Values are non-secret provider configuration. Timeout and active-close semantics are covered through controlled transport tests; they are not claimed as real DeepSeek evidence.

## Phase 2B Real Provider Process-Only Credential Passthrough Fix — 2026-08-13

### Root cause

`scripts/v061_acceptance_environment.py::build_manifest()` previously copied all `.env` values, including provider-key placeholders, into the generated acceptance manifest. Both FastAPI launch paths then constructed the child environment as:

```text
parent os.environ copy
→ manifest environment update
```

Consequently, an empty persisted `DEEPSEEK_API_KEY` placeholder overwrote an approved credential inherited from the parent process. `REAL_PROVIDER_VERIFICATION` also had no explicit process-only preservation contract. The same defect class applied to the existing OpenAI, Anthropic, Google/Gemini and OpenRouter provider-key variables.

Only the FastAPI child requires provider credentials. PostgreSQL preparation, Preview, browser manifests and frontend state do not.

### Secret-safe contract

The acceptance environment module now owns a bounded provider-secret allowlist:

```text
OPENAI_API_KEY
ANTHROPIC_API_KEY
GOOGLE_API_KEY
GEMINI_API_KEY
DEEPSEEK_API_KEY
OPENROUTER_API_KEY
```

These variables, plus the non-secret `REAL_PROVIDER_VERIFICATION` execution control, are process-only. They are excluded from generated manifest environment data. Child environment construction now:

```text
copies the parent process environment
→ applies manifest-authoritative non-secret acceptance configuration
→ preserves approved process-only values only when present in the parent
→ removes process-only values when absent from the parent
```

Thus an empty or stale manifest placeholder cannot erase, invent or resurrect a credential. Ordinary non-secret acceptance settings continue to override parent values as before.

`MOCK_PROVIDER` remains `true` for ordinary acceptance. When `REAL_PROVIDER_VERIFICATION=true` is present in the launching process, generated non-secret acceptance configuration sets `MOCK_PROVIDER=false`, preserving the established real-verification isolation contract.

Both the supervised acceptance FastAPI launcher and the legacy trusted-session stack now reuse the same child-environment constructor. No provider adapter, registry, TextModelNode, generation, SSE, cancellation, frontend, schema or migration behavior changed.
