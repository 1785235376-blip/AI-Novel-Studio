# V0.7.0 Phase 3A Read-Only Visual Text Workflow Contract Report

## Final Decision

`V0.7.0 PHASE 3A FINAL VERIFICATION = PASS`

Phase 3A exposes the existing provider-neutral text route as a versioned, read-only inspection contract. It does not add workflow execution, persistence, mutation, provider fallback, or a second provider.

## Authorized Scope

- Versioned workflow DTO/schema
- Pure runtime-to-workflow composition adapter
- Trusted, workspace-isolated GET API
- AppShell-compatible Chinese-first inspection surface
- Contract, authorization, secret-safety, frontend, build, token, geometry, and Mock Chromium verification

Explicitly deferred: executable node editor, graph persistence, second provider, credential storage, provider administration, desktop packaging, Phase 3B, and V0.8.

## Architecture

The authoritative execution route remains unchanged:

`author workflow -> application generation request -> TextModelNode -> ProviderRegistry / ModelRegistry -> existing provider/runtime -> SSE -> Diff -> explicit Accept -> Revision`

The new adapter only reads safe registry descriptors and resolves the explicitly selected `(provider_id, model_id)`. It does not call a provider, create a generation job, snapshot context, mutate a manuscript, or create a revision. No `GraphExecutor`, `WorkflowExecutor`, `NodeRuntime`, or equivalent alternate execution boundary was introduced.

## DTO Contract

- Contract version: `visual-text-workflow/v1`
- DTOs reject unknown fields with `extra=forbid`.
- Minimal graph: `上下文 -> 文本模型 -> 生成结果`.
- Model identity remains `(provider_id, model_id)`; labels are presentation-only.
- The adapter requires TEXT modality plus streaming support. Unsupported or unknown capabilities fail with `CAPABILITY_NOT_SUPPORTED` before any provider request.
- Capability metadata is allowlisted and display labels pass a sensitive-marker guard.

## Runtime Mapping

- The graph binds only to the explicit model selection already used by generation requests.
- No model selection produces an author-readable unresolved/empty state.
- There is no `first available` substitution and no hidden provider fallback.
- Existing SSE, cancellation, Diff, Accept, AI_ACCEPT revision, history, and restore-as-new-revision contracts were not modified.

## API and Authorization

Read-only route:

`GET /api/collaboration/workspaces/{workspace_id}/projects/{project_id}/storylines/{storyline_id}/branches/{branch_id}/visual-text-workflow`

- Trusted session resolution and existing membership/scope/domain authorization execute before composition.
- Unauthorized/cross-workspace access is denied.
- POST is not supported and is verified as `405`.
- Write endpoints: 0.
- Frontend does not fabricate ActorContext.

## Secret and Context Safety

- API keys, authorization headers, environment values, provider secrets, prompts, and private context content are absent from the DTO.
- Backend tests inject a sentinel into registry metadata and prove it is absent from DTO/API serialization.
- Frontend rendering applies defense-in-depth redaction and proves the sentinel is not rendered.
- Context is represented only as a structural stage; no full prompt or private context is exposed.

## Frontend and Accessibility

- Added one Chinese-first read-only inspection surface inside the existing AppShell navigation and panel architecture.
- No Run, Save, Add Node, connection handle, topology editing, or raw JSON UI exists.
- Loading, unauthorized, error, and no-model states are author-readable.
- Semantic ordered content and a textual workflow representation preserve logical reading order and keyboard accessibility; information is not conveyed by position alone.
- Existing DS-v1.0 primitives and tokens are reused. No shell, global navigation, token family, system canvas primitive, or protected-surface redesign was introduced.

## Geometry

- no inaccessible workflow content
- no shell overlap regression
- readable textual inspection fallback
