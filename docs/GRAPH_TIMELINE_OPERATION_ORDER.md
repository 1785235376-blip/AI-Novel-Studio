# Original Graph timeline operation ordering

The existing timeline_export node editor now exposes explicit adjacent Up/Down controls for its existing edit_operations list. This changes only the original graph draft parameters, using the same closed parameter validator/update controller. It neither changes the source timeline nor saves, previews, dispatches or renders automatically. Source snapshot, source bindings, export profile and each operation's contents remain unchanged. The 40-operation combined budget is unchanged.

Operation order is meaningful. A split/duplicate-created clip must exist before a later operation uses it. Reordering is not a claim that dependencies or the final timeline are valid: the original GraphTimelineExecution.prepare path retains its ordered apply_timeline_edits validation before explicit dispatch. No parallel execution or second timeline owner was added.

Both new reorder and existing remove controls reject retained index handlers after node/identity/client replacement, including A→B→A, and recheck current edit permission/busy state. Invalid/no-op indices do not update the draft. Existing source bindings are not rewritten when an operation is removed; original validation remains responsible for rejecting invalid references.

Evidence: graph-timeline-operation-order-r1, 3 focused controller/mounted component tests and TypeScript PASS. The tests check exact preservation/nonmutation, stale/unauthorized controls, explicit adjacent UI and normal removal. No transport is used. No new backend implementation, live browser, render, production build or full suite is claimed. Current cloud product-browser reachability remains blocked as recorded in v2/ci-browser-observation-20261018.json.

## Original track authoring controls

The same node editor now offers explicit track.update authoring for an existing, exact-bound original track: disable/hide/mute, audio-track gain and schema2 role. Video gain remains zero; schema1 does not acquire role or lock fields. Locked tracks are not implicitly unlocked. The controls append a normal ordered operation to the existing graph draft and reuse the original 40-operation/binding cap and parameter validator. No auto Save, timeline write, preview, dispatch or render.

The existing formDirty integration covers track inputs, preserving the original graph navigation/discard behavior. Form ownership now includes the bound timeline snapshot and current node lifetime; old input callbacks cannot attach to a replaced source/node. Moving between clip and track modes requires explicit target reselection, so clip gain/mute are not silently reused as track settings. A changed source pauses pending input with a visible explanation and the existing discard action.

Evidence: graph-track-authoring-r1 has one real File original timeline test plus seven focused UI/controller cases and TypeScript PASS. The File case applies the same original track.update operations, proves order-dependent values, explicitly saves and reopens original owners with unchanged source asset pins, and rejects changes to a locked track. It is not a full graph dispatch/render test. Final graph-track-authoring-final-r2 has eight focused cases and TypeScript PASS with valid frontend-normalized timeline fixtures. The intervening final-r1 failed on new fixture validation (missing video geometry and schema1 image-kind incompatibility); fixtures were corrected to valid video/audio rows, no runtime validator weakened. All failed receipts/logs are retained. No full suite/build or product browser acceptance added.
