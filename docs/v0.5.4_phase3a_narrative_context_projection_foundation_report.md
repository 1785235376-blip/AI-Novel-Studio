# V0.5.4 Phase 3A Narrative Context Projection Foundation

Date: 2026-08-09

## Decision and scope

`V0.5.4 Phase 3A: PASS`

Phase 3A adds a read-only NarrativeContextView, deterministic selection and truncation, and Writer-only delivery. Phase 1 through Phase 2C remain frozen. No rule, migration, UI, embedding, inference, automatic expectation, or narrative mutation was added.

## Architecture and read-only contract

`NarrativeContextBuilder` bulk-loads one logical snapshot of threads, foreshadowing, mysteries, character goals, NarrativeEvents, ChapterNarrativeLinks, expectations, and persisted findings. It constructs the view entirely in memory and does not invoke NarrativeFindingService or any repository write method.

NarrativeEvent remains the only authoritative progress source. ChapterNarrativeLink is used solely as an explicit relevance signal for the current ChapterVersion. Ten repeated builds and File/PostgreSQL before/after snapshots left state, findings, expectations, events, links, Lore, and Continuity data unchanged.

Migration decision: `NOT REQUIRED`. NarrativeContextView is a dynamic projection and has no table, cache, or CRUD repository.

## Feature flag and integration

`ENABLE_NARRATIVE_CONTEXT` defaults to `false`. When disabled, ContextService returns before narrative retrieval: no repository query, serialization, placeholder, or narrative token allocation occurs. The final context dict remains byte-semantically compatible with the Phase 2C baseline.

When enabled, ContextService adds `narrative_context` through the existing ContextEnvelope/final pack path. The envelope field is optional for backward compatibility. `AgentRunner` preserves the field only for the explicit `writer` role and strips it from editor, planner, reviewer, continuity, and other agents.

## Deterministic selection

Selection uses structured inputs only. Priority and reasons are:

```text
CURRENT_CHAPTER_LINK
CURRENT_CHARACTER_GOAL
ACTIVE_THREAD
ACTIVE_FORESHADOWING
OPEN_MYSTERY
ACTIVE_CHARACTER_GOAL
OPEN_FINDING_FOR_SELECTED_ENTITY
OPEN_FINDING
```

Within equal priority/category, stable entity ID is the tie-breaker. No title matching, chapter-text scan, created-at importance, LLM, embedding, or reranker is used.

Current Chapter links select their entities at highest priority but do not establish progress truth. Current characters come only from `current_story_state.active_characters` and prioritize matching CharacterGoals. Fallback includes active/open state under budget.

## Projection contents

PlotThread, Foreshadowing, Mystery, and CharacterGoal entries expose concise identity, status, a stable reason, active expectation summaries, and at most the latest authoritative NarrativeEvent projection. CharacterGoal also exposes character ID.

Only OPEN NarrativeFindings are included. Every finding is marked `advisory_only: true`; resolved findings are excluded. Finding projection carries ID, type, status, severity, subject, description, expectation IDs, Evidence IDs, ChapterVersion provenance, and reason. Full Evidence content is not duplicated.

## Token budget

`NARRATIVE_CONTEXT_TOKEN_BUDGET` is an independent configurable allocation and defaults to 800 estimated tokens. Lore retains its existing 2000-token budget, so call order cannot consume the other projection's allocation. Cost uses stable compact JSON length divided by four. Candidates are greedily admitted in deterministic priority order; overflow sets `truncated=true` without random dropping or LLM summarization.

The tests verify identical selected IDs, reasons, ordering, estimated token use, truncation, and serialization across three builds and repository restarts.

## Known limitations and remaining work

The token estimate is deterministic character-based estimation rather than provider tokenizer output. Phase 3A projects concise persisted state only; it does not summarize, infer, score literary quality, or expose a UI. Remaining work belongs only to a future explicitly requested phase. This implementation stops at Phase 3A.
