# V0.5.4 Phase 2C Deterministic Narrative Progress Rules

Date: 2026-08-09

## Decision and scope

`V0.5.4 Phase 2C: PASS`

Phase 2C adds only `MYSTERY_ANSWER_BY` / `MYSTERY_OVERDUE` and `CHARACTER_GOAL_PROGRESS_BY` / `CHARACTER_GOAL_STALE`. Phase 1, Phase 2A, and Phase 2B contracts remain frozen. No inference, automatic expectation, Writer Context integration, LLM behavior, UI, or additional narrative rule was added.

## Source-of-truth contract

`NarrativeEvent` remains the only authoritative narrative progress source. `CHARACTER_GOAL_STALE` reads only project-owned events whose exact type is `CHARACTER_GOAL:ADVANCED`. It never reads ChapterNarrativeLink as a second truth source. A controlled orphan-link fixture without an event remained stale; adding the authoritative event resolved the finding.

## Expectation semantics

Both expectation types use the existing `NarrativeExpectation` and `narrative_expectations` persistence. They require an explicit positive chapter deadline and an entity type matching the expectation type. `active=false` expectations do not generate findings.

The API verifies that the Mystery or CharacterGoal belongs to the route project. For Phase 2C expectations it also resolves current ChapterVersion and every Evidence ID, rejecting cross-project provenance.

Migration decision: `NOT REQUIRED`. Migration 009 stores expectation payload as JSONB and has no database enum requiring expansion. Migrations 009 and 010 were not changed; Migration 011 was not created.

## MYSTERY_OVERDUE

An active `MYSTERY_ANSWER_BY` generates a finding only when the current chapter is greater than its explicit deadline and the project-owned Mystery is `OPEN` or `DEVELOPING`. At the exact deadline there is no finding. `ANSWERED` and `ABANDONED` resolve an existing finding and never generate a new one.

Finding identity continues to hash project, finding type, subject ID, and expectation ID. Current chapter, timestamps, status, description, and backend do not affect identity. Repeated checks persist one finding. Mystery terminal reopen is not applicable by domain contract.

## CHARACTER_GOAL_STALE

An active `CHARACTER_GOAL_PROGRESS_BY` generates a finding only after its deadline when the project-owned goal is `ACTIVE` and no qualifying authoritative event exists. `SUSPENDED`, `COMPLETED`, `FAILED`, and `ABANDONED` goals are excluded. Exact deadline is not stale; deadline plus one is stale.

An explicit `CHARACTER_GOAL:ADVANCED` NarrativeEvent resolves the finding. Mentions, unrelated event types, and orphan ChapterNarrativeLinks do not qualify.

## Registry and finding lifecycle

The explicit stable rule order is:

```text
THREAD_STALE
FORESHADOWING_OVERDUE
MYSTERY_OVERDUE
CHARACTER_GOAL_STALE
```

Duplicate rule IDs remain rejected. `NarrativeFindingService` now reconciles successful rule results: absent violations resolve, repeated violations remain idempotent, and redetection reopens the same ID. Rule evaluation is isolated; if one rule fails, other rules continue and old OPEN findings owned by the failed rule are not falsely resolved.

Deadlines are explicit integer chapter positions.
