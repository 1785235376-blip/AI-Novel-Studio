## Implementation

The migration report now contains `imported`, `updated`, `skipped`, `conflicts`, and `failed` arrays. Every item records `table`, `source_id`, `target_id`, and `reason`; `summary` contains per-table counts.

Canonical JSON comparison ignores object-key order while preserving array order. Timeline, Secret, and Foreshadowing use separate fixed UUID5 namespaces.

Migration order is Novel metadata → Locations → Characters → Timeline → Secrets → Foreshadowing → Story State → Chapter/Document/Version → Summary → Canon/Pending Canon → Generation Job.

## Context migration coverage

- Novel metadata merges Style Profile and Secret source-ID mappings without replacing unknown metadata.
- Locations and Characters use `novel_id + slug`, preserve `_source_order`, and update changed JSONB fields.
- Character location slugs resolve through migrated Locations; unresolved references become conflicts.
- Timeline and Foreshadowing preserve `_source_id/_source_order` in details.
- Secrets use stable UUIDs and Novel metadata mappings.
- Story State performs insert/update/skip by `novel_id + chapter_number` and skips empty sources.
- Summary compares and updates one existing synchronization target instead of adding duplicates.
- Chapter/Version detects newer PostgreSQL versions and same-version document differences as conflicts.
- Canon/Pending Canon compare persisted values; Canon business IDs remain inside fact values.
- Existing Generation Jobs with different status or payload become conflicts and are never overwritten.
