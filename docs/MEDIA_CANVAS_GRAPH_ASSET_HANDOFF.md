# Media canvas card to original executable graph

2026-10-18. A saved, clean media canvas can now explicitly stage its selected asset card as an original `asset_reference` node in the current media/image/video graph. The user requests a fresh Asset metadata check, sees the exact ID/version/kind, then explicitly consents to adding one local draft node. The existing graph controller owns undo/redo and later CAS saving. No media bytes are copied, no edges or models are selected, no schema is automatically upgraded and no run is created.

The source card/selection/permission lifetime and target graph owner/draft/catalog/selection lifetime are fenced separately. Metadata must match the card's exact ID/version/digest/kind and not be deleted. A late read after source, target or permission ABA is discarded. A consumed apply callback cannot insert twice. The existing controller checks its current insertion/dirty/execution guards, original schema catalog, node count and image-only source rule. The original whole-graph save/execution continues to verify source access and content; this metadata preflight does not claim binary verification.

Evidence: canvas-graph-handoff-final, 51 tests passed, TypeScript and Vite production build passed, shared UI token guard passed. Tests include actual original controller insertion, undo/redo, stale handoff rejection and CAS save without creating a run, plus existing Media canvas dirty-owner and reviewed Director handoff regressions. The first run had 50 passes and one new harness error because its partial StudioClient omitted the original selection-preview Asset method. That method was supplied; product behavior and assertions were retained. Original failed log remains.

This slice has no backend/schema changes. Existing File/PostgreSQL source-binding/save authority is reused, not rerun as a broad suite. Frontend transport fixtures are not a real browser or live database end-to-end claim. Display-card groups are still separate from executable nested subgraphs. This is one practical bridge in the unified workspace, not completion of the professional Director workbench.
