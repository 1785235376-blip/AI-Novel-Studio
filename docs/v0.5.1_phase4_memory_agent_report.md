## Implementation

Added `memory_agent` to the existing Agent Registry through `prompts/memory_agent/system.md`. The agent accepts one exact accepted Chapter Version plus filtered related Character, Canon, Timeline, Secret and latest Novel Memory Snapshot data. It does not read arbitrary database content.

The strict output model accepts only `CHARACTER_MEMORY`, `RELATIONSHIP`, `EVENT`, and `SECRET_CHANGE`. Every Proposal requires confidence, payload, and at least one Evidence containing the exact chapter ID, chapter version, excerpt and locator. Mismatched Chapter Version references fail validation.

## Workflow

Chapter acceptance now queues a separate `MEMORY_EXTRACTION` Generation Job after the accepted version has been saved. Queue or extraction failure is caught and cannot roll back or fail Chapter Accept.

The extraction job:

1. loads the exact accepted version;
2. builds a filtered input;
3. invokes `memory_agent` through the existing model router;
4. validates strict JSON;
5. creates immutable Evidence;
6. creates PENDING Lore Proposals and Evidence relations;
7. records COMPLETED or FAILED independently.

It never approves a Proposal, updates Character/Canon, or creates Character Memory.

## Idempotency

Generation Job, Evidence and Proposal IDs use a fixed UUID5 namespace derived from novel, chapter, version, proposal index and canonical payload/evidence. Reprocessing the same accepted version returns the existing records rather than duplicating them.
