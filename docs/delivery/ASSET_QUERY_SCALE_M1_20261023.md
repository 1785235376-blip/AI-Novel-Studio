## 实现与支持边界

沿现有 Asset File owner 增加有版本的派生 SQLite 索引；没有第二套正式资产存储，也没有修改资产写路径。源目录 fingerprint 检测插入、删除、原子替换和原地改写；同步重建使用 staging + SQLite transaction + atomic replace。候选按原 owner 权限/功能/删除可见性和 Studio 记录校验后计数，页内记录再经正式 owner.get。未分页与 offset 响应保持既有结构。

预算在接口文档中完整列出。源 JSON 50,000 项 / 256 MiB、单项 1 MiB；读请求的元数据与内容有累计预算；超限明确 503，没有部分成功或无限扫描回退。30 秒为统一协作式预算，不是阻塞 I/O 的强制 deadline。精确 total 是全匹配候选遍历，热点降低的是源 JSON 读取与分页前重复 owner.get，不宣称 O(页大小) 查询。

现有全投影还读取资产 bytes、lineage 和关系 owner。内容读取预算覆盖实际资产内容文件；其他 owner 延续原实现，其跨 owner 原子性与硬内存上限没有在本阶段实现。更便宜且具有明确版本一致性的元数据分页由 M2 提供。

## 真实验证

环境与 M0 主环境相同：Python 3.12.14、FastAPI 0.161.1、Starlette 1.9.0、Pydantic 2.14.1、httpx 0.28.1。原 M0/查询/资产回归在索引接入后 **49 passed, 3 warnings in 8.10s，exit 0**。新增索引路由组 **8 passed, 3 warnings in 7.00s，exit 0**，包含一个辅助 EIO 故障注入测试，未把它写成真实磁盘故障。

命令均带 M0 文档所列隔离环境变量；原回归命令替换 `--basetemp` 为 `.runtime/asset-scale/m1-regression`。新独立真实路由测试：

```bash
python -m pytest -q tests/test_studio_asset_query_indexed.py \
  --basetemp="$PWD/.runtime/asset-scale/m1-final-indexed" --tb=short
python scripts/benchmark_asset_query.py --sizes 100 1000 10000
```

成本测试用 Python audit 观察真实源 JSON/bin open 与资产目录枚举，不替换存储。故障测试仅缩小预算或安排真实文件变化；非法/拒绝结果不带计数/标识/路径，保留 no-store；正常只读及预算拒绝测试中源文件内容/stat 保持不变；源变化测试的写入由测试注入，查询实现不写正式源数据。派生索引和操作锁写入不冒称全文件系统零写入。

基准每规模由独立进程启动并执行冷查询、热查询、深分页、低命中关键词、六种类型、精确 total 空页、旧无分页；持久索引另起进程冷重开。样本为真实 File 元数据及每项 36 bytes 内容，测的是元数据规模，不是大型媒体；未清空操作系统页缓存。内存峰值为 tracemalloc，RSS 为进程峰值；SQLite C 层读取不在 Python source-open 计数中，另列索引文件大小。
