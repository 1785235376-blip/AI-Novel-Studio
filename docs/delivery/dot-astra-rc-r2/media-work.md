# R2 media and asset work

Baseline inherited: `f8c141c39a543cc9dbea57647ac91185bc9aecd6`. This is implementation/test evidence on the R2 work branch, not a released product or a real-provider quality certification. Main implementation model: the platform's `gpt-6-astra`; no provider credentials, paid services, real user manuscripts or voice recordings were used.

## D10: images, visual references and asset lifecycle

Before: direct image requests kept component-local status, replaced inline images with unusable history markers, fixed most generation parameters, and imported unverified bytes. Generic asset reads trusted recorded size/digest, asset IDs could construct filesystem paths, and deletion removed originals. Visual memory was metadata with no real index.

After:

- A separate persisted image production queue is connected to the existing IMAGE panel. It has create, execute, cancel, explicit retry/recovery, history, two-result comparison and explicit accept-to-library. Results remain PENDING approval until acceptance; only accepted, actually decoded PNG/JPEG/WebP bytes are imported. Late results after cancellation/retry cannot revive the previous attempt. Image and synchronous audio cancellation is explicitly LOCAL_RESULT_DISCARD; the UI warns that upstream computation may continue.
- Parameters are validated and mapped into the actual adapter request: size/quality for compatible image APIs; width/height/steps/seed/negative prompt for Automatic1111 and ComfyUI. Unsupported parameters fail instead of pretending they affected generation. Reference editing uses the adapter's actual edit method.
- Production queues are partitioned by project, branch and resolved actor, not by session token. A new session for the same actor can rediscover its jobs. Every API operation reauthorizes the current project/branch membership; approved library assets are branch-shared according to existing permissions.
- The earlier direct-generation UI remains for compatibility. Its historical inline markers are not repairable original images; the persistent queue is the recoverable path. The two paths are labelled distinctly. A future UI pass may consolidate them without removing persisted review/cancellation behavior.
- Asset handling now validates identifiers, rejects symlinks, checks bytes against SHA-256 and size at read, distinguishes idempotency collisions, atomically writes content/metadata, uses cross-instance/process mutation coordination, retains recoverable tombstones and supports restore. Lineage metadata validates same-project/branch sources and cycles.
- Reference creation → explicit version-guarded approval → persisted lexical/metadata index → retrieval is connected to the existing asset inspector. Approval captures actual asset digest/version and source provenance. Changed/deleted/missing/tampered references are excluded until re-reviewed. No embeddings or visual semantic consistency are fabricated: responses explicitly say LEXICAL_METADATA, embeddings_available=false, inference_performed=false.

Detailed asset APIs/UI/tests are in `assets-work.md`. New image routes: GET/POST `/api/novels/{nid}/image-jobs`; POST `/{job_id}/execute|cancel|retry|accept`.

## D11: motion, downloads and actual cut assembly

- Submission claims an execution token under a lock, releases the lock for the provider request, and reloads authoritative task state before committing. Cancel/retry wins over late success or failure. Duplicate submissions of a queued remote job are rejected. Provider/model/frame configuration is frozen while active or completed.
- Local `asset:`, `shot:` and `storyboard:` references must resolve to a real image in the same project/branch and decode successfully. A shot without an actual rendered asset is rejected. Asset digest/version provenance is captured. Opaque external HTTP frame references remain marked `content_verified=false`; their upstream rendering is not claimed verified.
- Locally stored frames remain local unless their own effective privacy permits cloud transmission. A separate explicit per-task motion prompt review is bound to the exact current prompt hash, provider and model. Unknown prompt privacy is local-only; changing the model/provider invalidates review. The inspector displays the exact prompt and target before the author can permit cloud use. Routes: GET/PUT `.../motion-tasks/{task_id}/privacy`.
- Provider callbacks retain the existing configured secret-token mechanism and now require the matching remote task ID and submission key. Duplicate terminal callbacks are idempotent; a replay cannot replace terminal media, resurrect cancellation or regress progress. This is a shared-secret contract, not a claim of per-vendor asymmetric signature support.
- Media downloads use a new strict policy independent of the legacy loopback allowlist. A user-configured local provider's exact loopback/private-literal or localhost origin can serve its own output; arbitrary DNS aliases do not inherit private-network access; unrelated private ports/hosts, link-local/metadata, reserved, multicast, credential-bearing URLs, redirects, compressed responses, oversized/truncated data and non-HTTP schemes are rejected. DNS resolves once and is pinned for the socket connection; HTTPS retains the original TLS hostname. Requests send no provider credentials to returned output URLs.
- Downloaded video must have a supported real container, valid stream/duration, bounded resolution and successful single-threaded ffprobe/ffmpeg decode. HTML errors, corrupt streams and missing validators fail without creating an asset. Successful imports keep the measured duration, digest and actual source task association.
- Added local clip assembly using verified owned assets only: author-selected clip order and start/end trims, 1–30 clips and ≤10 minutes, bounded subprocess execution, persisted source-version/digest manifests, and real decoded MP4 output. The VIDEO inspector exposes the form and history/download. Output is explicitly a 640×360 24 fps VIDEO_ONLY silent review rendition. No soundtrack mix or final-master quality is implied, and original files remain recoverable. Routes: GET/POST `/api/novels/{nid}/screenplays/{screenplay_id}/video-assemblies`.
- Screenplays/motion tasks retain the product's deliberate branch-shared collaboration semantics. This differs from actor-private image/audio pre-review queues; the API guards project, branch and membership rather than falsely claiming per-session manuscript copies.

## D12: persistent voice and chapter audio

- Voice bindings/pronunciation dictionaries remain durable. Optional voice licensing/provenance notes persist into jobs/export manifests. Synthetic tests use generated silence and solid colors dedicated to CC0; no real person's voice is used.
- Chapter queues capture immutable spoken text, pronunciation replacements, source version/full-content digest and effective privacy. Immediately before synthesis, current session access and the current chapter are rechecked. Remote execution requires unchanged source version/digest and both captured/current explicit source consent. A later approval cannot retroactively upgrade an unreviewed queued snapshot; source edits/revocation block before the external call.
- Store read-modify-write is serialized; corrupt JSON fails closed and history/active tasks are not silently truncated. Idempotency keys are checked against the actual request. Execution-token fencing protects concurrent cancel/retry/stale recovery; failed/retried attempts cannot duplicate final generation records.
- Real binary TTS responses are supported, not only JSON URLs. PCM WAV is parsed without an optional codec tool; other supported audio containers need real codec validation. Success requires actual verified bytes, measured duration and an owned library asset. Unsupported asynchronous-only speech providers report their missing polling adapter honestly.
- Unsupported emotions are rejected. No `[emotion:...]` string is injected into spoken text. The UI exposes neutral emotion for the currently mapped contract, identifies that unsupported capability, and provides voice authorization notes.
- Per-sentence chapter queues retain original order and optional selected character voice binding. Completion can arrive out of order; the chapter manifest projects the latest production group in source order. Existing chapter source contracts are shared project chapters plus ChapterVersion, while production jobs are actor/branch-bound.
- Authenticated audio/video preview uses the existing API download path and in-memory object URLs, preserving session headers without placing tokens in URLs/storage. Subtitle timecodes remain explicitly ESTIMATED; measured media duration is displayed separately.
- Single verified audio files can export unchanged. Multiple same-format PCM WAV segments concatenate in selected/source order with the configured pause and a measured duration/hash/source manifest. Differing PCM formats or incompatible pauses fail instead of silently remixing. The pause setting is disclosed as subtitle-estimation/segmented-WAV assembly behavior, not a fabricated provider capability.
- Added POST `/api/novels/{nid}/audiobook/chapters/{chapter_id}/queue-segments` and `/export` (audio or manifest). The existing audiobook panel contains the queue/export actions.

## UI and API boundaries to preserve

Existing AppShell, ModuleWorkspace, design tokens, primary IMAGE/VIDEO workspaces and collaboration remount protection are preserved. New panels are domain consumers: ImageQueuePanel, VideoAssemblyPanel, MotionPrivacyPanel, AuthenticatedMedia; AudiobookManifestPanel and existing inspectors are extended. Async result updates check project/actor/branch/session render identity and unmount; repeated submissions are fenced in the frontend and again in backend state transitions. The central API client retains both context-pinned downloads (export work) and POST binary downloads (audio work).

## Explicit remaining limits

1. No real image/video/TTS provider or model-quality checks ran; no paid calls or keys were available/used. Vendor APIs that differ from the existing compatible HTTP contract still need dedicated adapters and authorized real integration tests. No automatic paid fallback is introduced.
2. The optional ffmpeg/ffprobe binaries were already present in the Linux test environment. They are not bundled or licensed for Windows distribution by this change. Capability health reports their presence, and media processing fails closed when absent. A Windows packaging/licensing decision remains required.
3. No trained visual embedding index or semantic visual-consistency inference exists. The implemented index is honest approved-reference lexical/metadata retrieval.
4. Automated multi-character dialogue detection and phoneme-aligned subtitle timings are not implemented. Authors can bind a selected character to segments; source segmentation is deterministic. Mixed sample-rate/codec audio transcoding and full soundtrack mixing are not provided.
5. Video assembly is a basic silent review cut; final-master presets, compositor effects, audio mux/mix, arbitrary NLE interchange conformance and true vendor callback signatures remain separate work. External frame URL content and model-generated scene continuity remain unverified.
6. File-backed audio/image orchestration assumes the packaged single service process. Asset storage has cross-process mutation coordination; full multi-worker media orchestration/database leases are not claimed.
7. Missing/stale asset/voice-license/legacy task state is surfaced; historical lost inline images and absent source consents are not reconstructed or silently treated as approved.
