# Explicitly discard one original queued node task's local adoption

Starting point: `e28baafe73b9074ee7f7da8a814637a5958f196f`. A still-matching empty Canvas already allows cancellation through the existing continuation panel. The uncovered case is an original queued task whose Canvas has changed or cannot be read. Its task remains owned and readable, but the Canvas-dependent continuation cannot open it. The independent Job metadata entry remains pure read-only; this slice adds a separate explicit action.

## Original cancellation, narrow eligibility

`POST /api/projects/{nid}/studio/production/jobs/image/{jid}/node-discard` accepts only the original `expected_version`, `expected_request_digest` and literal `confirmed:true`. False, numeric/string coercions, missing confirmation and client-supplied snapshots are rejected. Existing-owner-only covers the entire original invoker. Original `domain.read` and current `domain.write` are checked separately, with the same actor/scope and combined original guards. A successful read is not write authority.

Only the original standalone local, source-free `m5.image.t2i` QUEUED task with attempt zero and no execution, candidate, output, publication, review or prior cancellation evidence is eligible. RUNNING, UNKNOWN, waiting-review and completed tasks are outside this new action. The captured command and context must reproduce the original preview request digest, using its original formula and stored recipe metadata rather than querying current configuration. The target is an original request capsule; the action does not read or verify the current Canvas.

Only the existing Production → Image cancel owner writes. An optional **server-only** expected raw snapshot is compared inside the original `_mutate`, after ownership and CAS checks and before any early return or state advance. That comparison performs no IO, guard, import or new lock under the queue fence. The original default `None` path retains its existing call shape and behavior. There is no outer queue lock spanning project or authorization reads and no new task/state owner.

The original owner changes only the Job to CANCELLED with `LOCAL_RESULT_DISCARD`; source and candidate evidence is preserved. It does not stop remote computation or delete media. The closed `studio-image-node-job-discard/1` ACK contains the original target/incarnation, safe 26-field Job projection, `canvas_read:false`, `automatic_actions:false`, `local_result_discarded:true` and `remote_stop_confirmed:false`. It checks the exact same Job/request/command/provider, version advanced by one and only the cancellation fields changed. Projection uses the original cancel return directly, without a post-commit lookup. Requests are bounded to 4 KiB, responses to 256 KiB; errors use safe fixed codes, `no-store` and `nosniff`.

## Confirmation and uncertain outcomes

The separate task-row action prepares an exact metadata snapshot using the existing protected Job observation. It preserves unrelated drafts and opens neither an editor nor Production. The user must acknowledge the local-only effect and explicitly confirm that current snapshot. Refresh, changed permissions, source/project/client/method/read changes, A/B/A, old handlers and unmount invalidate confirmation.

The client validates the closed ACK. Its actual-send hook runs after local validation and immediately before the protected POST. The helper checks currentness and consumes an ephemeral workspace claim for the original project/incarnation/Job/version/request digest. Closing and reopening the same snapshot does not permit another send in that workspace. This is a UI guard, not a durable operation owner or a claim of network exactly-once execution.

Once a method may have sent, every missing or invalid ACK—including 403, 409, timeout, abort or a late response—is **UNKNOWN**, never a rollback or a successful discard. An embedded client that omits the send hook cannot manufacture success; its uncertain invocation also blocks reuse of that snapshot. No automatic retry, requeue or confirmation replay follows. The bounded race also settles the host write wrapper when an embedded method ignores abort, while the UNKNOWN trace and consumed claim remain.

Recovery uses explicit original task-list/detail reads of the same Job with the owner-supplied new version. Only a current read matching the original identity/incarnation/target/request and exactly the next CANCELLED version can confirm that task's state; it does not attribute the state to a particular HTTP request or confirm remote stop. An absent or still-queued snapshot is not proof that an earlier request rolled back. Traces are independent per claim, so another task's ACK cannot erase an earlier UNKNOWN. On permission loss or context change, identifiers/digests from these discard traces are hidden in both status displays and departure warnings; only a generic unresolved count remains. Existing other owners' departure records are unchanged. No persistent discard hint or cold-browser guarantee is added. The original owner CAS prevents duplicate state advancement.
