# Read an original node Job independently of its Canvas

Starting point: `6e6fcd72a09622e600c3f357e5f6bd6ef449072b`. Original node continuation requires its captured empty Canvas, and target comparison/view needs a readable Canvas and history. A later Canvas edit or unavailable Canvas therefore prevented a user from opening a failed task's metadata through those entries. Expanding resume status/action authority would not solve that dependency.

The task center now has an explicit **只读查看原节点任务** action. It stays in TASKS and shows the original status, failure code, attempt, times, saved input, provider identifiers and metadata receipt without opening Production, an editor or recovery. The target is labeled as a captured request, **not a checked current saved location**. Candidate pins record what the Job says; they do not establish readable content, a current asset or successful generated-node adoption. Original image-owner states are QUEUED, RUNNING, FAILED, UNKNOWN, AWAITING_REVIEW, REVIEWING, APPROVED and CANCELLED. The generic frontend's SUCCEEDED state is not claimed as an original image capability.

## Closed original-owner contract

`POST /api/projects/{nid}/studio/production/jobs/image/{jid}/node-observation` has the strict body `{expected_version, expected_request_digest}`. Original Host/principal/scope and `domain.read` remain authoritative. Existing-owner-only contexts cover the entire invoker; missing File identity refuses instead of being provisioned. Two original `_row` reads must agree on the full raw row and captured context. The original standalone, local, source-free text-to-image command, node capsule, project/scope/incarnation and any required receipt digest are checked. No Canvas, history, graph catalog, asset, provider, configuration, resolver, execution, reconcile, cancel, acceptance or review operation is called.

The exact six-key `studio-image-node-job-observation/1` response contains `job`, `target`, `incarnation`, `canvas_read:false` and `automatic_actions:false`. Its Job is a distinct, closed 26-field metadata projection; it is not a full ProductionJob and omits execution recipe, sources, media measurement and arbitrary dictionaries. The command is strictly decoded from the original command model; provider is four named metadata fields. Candidate is only validated ID/version/digest/kind, even if an older raw candidate object carries extra URI/data fields. This does not change or claim to sanitize the existing generic GET contract. Requests are limited to 4 KiB, responses to 256 KiB; safe fixed errors retain original authorization statuses, `no-store` and `nosniff`.
