# Prompt adoption UI integration

Base: `95420aa59acb4c196d92e7292df0744098f6d2ff`. This is a bounded UI implementation and preparation record. Real File/PostgreSQL browser acceptance and final source-frozen integration are recorded separately by their owners; passing component tests is not product acceptance.

The existing Storyboard Prompt adoption panel, disclosure and read client were already present and read-only. Their source and existing test bytes remain unchanged. The new adjacent panel performs no automatic read: “核对 Prompt 采用条件” uses the existing authorized adoption GET. Missing or false `write_enabled` keeps write controls absent. A true capability still requires the original host's explicit `writable` admission; the original backend remains the final authority.

The panel reuses `createPromptClient` for the authorized library, current head/detail, original revision bytes and explicit approval. It requires a complete, readable, unmasked current head and verified complete original bytes; it displays the exact source Asset/revision/digest and target document/Shot/version/digest before confirmation. Approval is a separate user action followed by fresh metadata and body reads. The adoption click never approves implicitly.

Only the original closed IDs/digests/CAS DTO is posted. Confirming freezes its request ID and complete body; an unknown response can retry only that identical request. Selection, document version, actor/branch identity, host write admission or gate changes replace the local session synchronously, clearing preview/consent and rejecting late responses. The original CreativeWorkspace `productionWork` serializes the mutation with its existing operation lock.

The write decoder requires `committed:true`, exact source and target proof pins, the original binding-verification contract, and the real result version. A replay may describe a later current document version while preserving an older proof result version; it is never equated with a currently applied Prompt. The panel re-reads adoption provenance and the original CreativeDocument, requires the current exact document version/digest, current `still_applied`, readable source and actual raw Shot `frame_prompt` equality. It then returns the original verified document to CreativeWorkspace's existing clean/current/unblocked document state only if the host still holds the exact original target version. A newer accepted host version throws rather than being overwritten or producing a success notice; the committed request remains settled and rechecking performs only reads. The original Storyboard controller reloads, and old provenance is closed so it cannot remain displayed as current.

Shot IDs are the original raw identity: backend `storyboard_receipt` assigns `shot_id = shot.id`, the original front-end `checkedStoryboardShot` requires equality, and `shotSummary` passes it through. The canonical `document_id:number` Prompt binding key is not guessed as an adoption target.

New independent tests are `PromptAdoptionWritePanel.test.tsx`, `promptAdoptionWriteClient.test.ts` and `CreativeWorkspace.adoptionCommitRace.test.tsx`.
