## Existing gap and bounded edit

The original editor added an unconnected checkpoint and removed a node with all its incident edges; authors had to manually reconnect dependencies. The new local helper previews one existing edge replaced with A → checkpoint → B, or removes an automatic checkpoint with exactly one incoming and one outgoing edge and reconnects A → B. The full authored definition and every unrelated edge/field are retained. It refuses ambiguous many-way reconnection, duplicate/self edges, unknown node references, unsupported extra edge fields, cycles, duplicate IDs and original node/edge/step-budget violations. It neither silently deduplicates nor raises budgets.

The original contract permits a single manual approval directly before the terminal reviewed artifact (`declarative_agents.py:147–157`). The helper never adds/removes a human approval and refuses insertion between it and the artifact. A checkpoint is an automatic marker in the original executor (`v1_capability_service.py:792–814`), not a human review or persistence checkpoint. The UI states this explicitly. Dependency reachability is preserved; unchanged relative ordering of ready branches is not promised.

Preview and apply make **no request**. The preview is explicitly structural and has not passed server validation. Apply only fills the current unsaved definition, resets original graph/model/output acknowledgements and preflight, and retires historical candidates/pending discard selection through the existing edit generation. Original Validate and Save remain separate actions; their server gates remain authoritative. Preview ownership changes on form edit, selection request/reload, history fill, directory refresh, saved identity/version/digest, busy/unavailable state and project/client remount. Old previews never return after an A→B→A context transition.
