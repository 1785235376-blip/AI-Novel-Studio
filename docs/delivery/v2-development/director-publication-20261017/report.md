## Scope and behavior

The original independent Director coordinator has one strict private opt-in:
`_dispatch_independent(..., terminal_evidence=False)`. The default adds no
preview, request, Job.public(), or public API payload field. Existing Graph,
anchored Director, private live review, and public-denial paths retain their
original owners. Existing request/payload fixture assertions passed unchanged.

When opted in, the original worker appends publication only after its existing
final post-emit generation-bounds guard. Earlier COMPLETED rows are provisional
and carry no terminal-history evidence. The original source/route/request,
proposal admission, original zero-settled ledger, actor/scope/project incarnation,
output digest and byte length, output contract, and bounded parameters are bound
in `_creative_director_terminal_evidence` in the original generation record.
No second text copy, new storage engine, scheduler, or retry path was added.

The historical record explicitly says authority and bounds were sampled at a
named pre-commit checkpoint. It does not assert authority was still live at the
physical atomic replacement. Later revocation, cancellation, or elapsed time
can block the existing live result while leaving history intact. There is no
new historical-evidence consumer, restored capability, durable review authority,
adoption route, or public activation.

Only the original worker/capability/callback and repository can publish. A
transient original-repository acknowledgment is accepted after owner/lock
unwind. Failure before replacement, replacement followed by an exception, and
lock-unwind uncertainty suppress the live result, retain once-only accounting,
and never retry publication or issue a destructive cleanup save.

Generic File saves cannot mint, replace, or explicitly remove evidence. Omitted
evidence is preserved from the original row, including through passive restart
and later live-output clearing. Strict supplied-envelope validation and
canonical equality reject bool/int and other numeric-type aliases.

## File coordination and compatibility

Publication order is the existing generation-accept lock, Job condition,
original raw scope, original project owner, then a distinct generation-write
leaf lock. No source/authority callback is acquired under the leaf. Every
File save performs its prior-row check and replacement under the same leaf,
using canonical, platform-normalized destination identity. A central pre-IO
basename guard rejects separators, NUL, dot/dot-dot, and Windows drive forms;
ordinary existing non-UUID basename IDs remain supported.

PostgreSQL publication is explicitly unsupported before admission effects;
generic PostgreSQL reserved-field injection is rejected. Its denial test does
not open a database. No PostgreSQL acceptance is claimed.

The existing File lock/atomic-replacement mechanisms are reused. This does not
claim hostile-filesystem, hard-link, native Windows, or power-loss durability
protection. The existing atomic writer fsyncs the temporary file, not the parent
directory. Native Windows execution was not performed.

This foundation does not solve durable pending review. Historical evidence is
non-consumable; public activation, restart authority, post-deadline review,
re-authorization, durable candidate adoption, and PostgreSQL publication remain
outside this implementation. Default mode remains off. The parent owns the
isolated-branch commit and any later integration decision.
