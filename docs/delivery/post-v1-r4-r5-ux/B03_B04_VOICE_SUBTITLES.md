## Functional journeys

1. Create a plan and licensed provider voice Profile in the original audiobook panel. Open **声音导演**, select that plan, and review each segment's role, speaker, voice, spoken text, delivery and pronunciation. Unknown speakers remain unassigned; quotations can be corrected to narration. Source manuscript text/offsets remain immutable, separate from reviewed spoken text.
2. Changing a segment invalidates only its bound speech. Unchanged audio IDs remain intact. Explicitly bind measured approved audio and lock satisfactory segments. Reordering reuses IDs and recalculates the measured timeline with each segment’s configured pause, without inventing starts after unmeasured gaps. New WAV bindings retain measured frame count and sample rate; pause boundaries are quantized to actual samples, with no trailing silence after the final segment. Older bindings retain their measured millisecond precision until rebound.
3. Approve the plan through the existing review authority, select unlocked segments and approve only those for queueing. No TTS runs on mount, edit, approval or queueing. Execute each queued segment explicitly. The original durable executor validates current actor/scope/plan/segment/source and provider configuration before dispatch and before committing results. Request retries with the same idempotency key reuse the same queue items.
4. The integrated route currently allows only explicitly configured local TTS with a zero external-cost limit. Remote spending is refused pending broker-budget integration. Missing runtime returns unavailable; emotion support is checked by the actual provider. The existing speech rate and pause settings are preserved. Pronunciation is bounded plain-text simultaneous replacement, without regex, cascading substitutions, SSML or external resource references. Reference audio / cloning input is rejected, rather than treating ordinary voice authorization as clone consent.
5. Actual generated WAV/audio is persisted as an owner-private asset, never automatically accepted. Read it through the authorized preview endpoint. Explicit output review promotes the same asset ID into the existing project asset library with a compare-and-swap version, retaining origin and provenance. A promotion retry can recover if the asset commit succeeded before the job-status update. Binding it back to a reopened plan is an explicit separate action.
6. Open **字幕时间轴**, bind an existing real audio/video asset and optionally a source plan. Create a manual draft, enter cue text/start/end integer ticks, select speaker segments and save a new version. Split at an explicit tick with explicitly entered left/right text; merge only adjacent rows with the same speaker link. Reversed, out-of-range, unsorted, empty and unexplained-overlap rows are rejected. Intentional overlap requires a reason. Reading-speed and line-length warnings are explicitly uncalibrated heuristics.
7. WAV PCM16 waveform peaks come from decoded audio samples; other formats show unavailable waveform. Timebase is a rational ticks-per-second ratio, including 24000/1001 and 30000/1001. Source WAV sample count/rate supplies exact rational duration. There is no proportional-by-text or fake word/phoneme timing. SRT/WebVTT exports quantize down to milliseconds, reject intervals below export resolution and parse the produced bytes back before returning the new file.
8. Caption records bind asset version/digest, source chapter snapshot, speaker/name/segment direction, linked audio binding and segment order. Relevant source, speaker, audio or ordering changes invalidate export and hide stale cue/waveform details. Local editor drafts survive conflicts and refreshes; scope changes reset them. All UI requests use the captured session/branch, with loading, empty, error, stale, conflict, retry and original-review navigation states.

## Shared-origin safety changes

- Directed plans are visible only inside an actor-bound ContextVar invocation with guaranteed reset. R3 generic list/read/review/mix and Inbox calls cannot reveal directed records to another actor or with the feature OFF. The original R3 segment editor cannot bypass the new review fields. The production service injects the shipped local PCM16 WAV mixer. Directed candidates retain actor ownership and inherited source-feature flags even through generic R3 lists and Inbox review. Disabling any required source origin hides its derivative mix and approved asset.
- Directed jobs live in the original store's actor/branch namespace, including local File mode. The generic legacy File queue remains unchanged. `AudioProductionStore.load` filters disabled-origin jobs and generations before counts; internal mutation reads preserve hidden rows rather than accidentally deleting them. Generic legacy execute cannot dispatch directed jobs without the explicit current direction guard. Generic recovery skips directed jobs; cancellation/retry are explicit in the new surface.
- Server-only asset create arguments `required_features` and `owner_actor_id` protect pending output. `get/list/content/update_metadata` accept captured server actor context; legacy calls without it cannot read private output. Exact branch and feature checks remain after promotion. Source-link derivations inherit origin restrictions, so a generic derived child does not expose a hidden new-origin parent.
- Legacy uploads/metadata edits cannot manufacture or clear top-level origin/owner/provenance markers. Public metadata and asset conflict envelopes strip these private markers. Ordinary unmarked assets retain their established signatures and behavior.

## Storage and rollback

Direction data extends existing R3 plans; caption rows use the existing scoped experimental document store under collection `subtitle_timeline_v2`. No SQL migration, startup migration, manuscript rewrite or destructive conversion is introduced. Tests parameterize the actual File/PostgreSQL storage implementations. Directed audio continues to use the original durable file queue and asset store, just as existing audio production does; this is not claimed as a new PostgreSQL audio-queue implementation.

The original chapter repositories do not provide branch-specific manuscript rows to R3 audiobook. B03 preserves `BRANCH_SOURCE_ADAPTER_REQUIRED` for collaboration base chapters rather than substituting another branch or pretending branch text exists. Real branch membership, owner isolation and rejection are verified; branch-specific creation/approval awaits that existing source adapter.

The task-center helper `voice_task_projection` reads only the captured actor/branch original queue, projects at most 100 current-scope safe status rows and returns `has_more`. It does not expose text, pronunciation, bindings, paths or raw errors.

Turning flags OFF hides the new origin and disables dispatch without erasing stored records. Do not open the new data directory with the frozen candidate. Use the already documented isolated-copy/export rollback practice.
