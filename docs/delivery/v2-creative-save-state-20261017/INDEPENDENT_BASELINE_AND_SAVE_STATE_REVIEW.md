One concrete state limitation is visible: every permitted `change` marks dirty true, including an unchanged value or editing a saved value back to its base. A narrow repair should compare the original documentInput projection against the actual saved base, preserving all persisted content. Object-key ordering may be canonicalized; scene/shot/dialogue/reference array order must remain significant. Metadata such as receipt timestamps and version do not belong in the editable comparison. No arbitrary body trimming or content deletion should make a real draft appear saved. A successful response must install its actual normalized row as both the new base and the editable value.

Draft preservation remains the primary boundary. An edited new draft without a saved base remains unsaved. Blocked or uncertain writes retain their original content and blocked state even if a structural comparison matches the old base; equality does not establish the outcome of an uncertain request. Existing hydration intentionally refuses to replace any existing stage draft, including a clean explicit-new draft; retaining only dirty drafts would weaken that behavior. Switching stages must retain each stage's draft and make other-stage pending content explicit. The original adoption callback target-version CAS and its rejection behavior must remain intact.

The focused acceptance should distinguish exact current-document state, other-stage drafts and original novel save status. Useful cases are saved-base no-op, edit then exact revert, real unsaved nested content, server-normalized save receipt, dirty content retained across stage changes, selected-stage hydration arriving late, and blocked/409/500 paths retaining content without a saved claim. Any common-status prop should preserve original connection and Tutor content while leaving novel save status owned by the novel workspace. Those are review boundaries and proposed evidence, not implementation or runtime PASS claims. The original collectors already include recursive frontend source, scripts, root Playwright config and e2e paths; no collector change is currently required.
