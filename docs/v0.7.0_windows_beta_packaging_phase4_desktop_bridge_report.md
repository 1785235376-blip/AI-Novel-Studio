## Host architecture

- Minimal C#/.NET Windows Forms host with Microsoft WebView2 Evergreen.
- No Electron, Tauri, Node desktop runtime, alternate backend, or alternate authorization layer.
- Launch data is read once from inherited stdin. Bootstrap material is never accepted through command-line arguments, environment variables, files, registry, URL query, or fragment.
- The host exchanges Phase 3 bootstrap directly with the loopback backend, retains the returned opaque token only in host memory, clears its bootstrap field, and injects the token into same-origin frontend `/api/*` requests through `WebResourceRequested`.
- Ordinary frontend JavaScript receives only an immutable packaged-host boolean marker. It never receives the bootstrap secret, session token, runtime identity, ActorContext, roles, or permissions.
- The existing frontend/proxy remains authoritative; the host neither executes business logic nor bypasses backend APIs.

## Lifecycle integration

- `PackagedDesktopLifecycle` composes the existing Phase 2 `RuntimeLifecycle` and Phase 3 `LocalSessionBootstrap`.
- Application READY requires runtime services, host startup, one-time bootstrap completion, an active protected session probe, and a running host.
- Backend readiness, desktop startup, and secure-session failures return bounded Chinese messages without raw exceptions or identifiers.
- Shutdown blocks actions, closes the host, invalidates all packaged sessions, then invokes Phase 2 runtime shutdown.
- Host crash invalidates the session and shuts down owned runtime services while preserving UserData.
- WebView profile data is constrained to the disposable packaging Cache/WebView2/runtime-instance directory; canonical UserData and NovelData are not browser-profile dependencies.
