## 4. Frontend Architecture

The existing React/TypeScript/Vite/TipTap application remains in place. TanStack Query owns server state, Zustand owns persisted session/scope selection, and local storage owns recoverable drafts and conflict records. Collaboration behavior is concentrated in the existing application shell and API client rather than a second frontend architecture.

## 5. Contract Changes

Typed contracts now cover bootstrap/current actor/capabilities, workspace members, permission summary, scoped chapters, revisions, audit entries, ContextSnapshot metadata, and generation-to-snapshot linkage. Contract tests verify the nine collaboration routes and their OpenAPI response models. Runtime errors preserve distinct 403 and 409 meanings.

## 6. Backend Gap Changes

The backend adds authorized, explicitly scoped collaboration read APIs and reuses the V0.5.6 repositories and authorization services. Requests use a trusted opaque `X-Session-Token` and explicit Workspace/Project/Storyline/Branch scope. Active membership, `domain.read`, project ownership and resource scope remain server-authoritative. Unintegrated collaboration routes remain fail-closed.

Generation creation now captures `base_chapter_version` before dispatch and returns it to the client so AI acceptance cannot silently adopt a newer chapter version. No database redesign or migration was required.

## 7. Scope Navigation UX

The current Workspace, Project, Storyline and Branch are always visible. Connection requires an opaque token and all four scope identifiers. Chapter listing and query keys use the complete scope fingerprint. Switching scope clears the selected chapter, cancels pending debounce work, isolates cached data, and rejects late responses from the prior scope.

## 8. Actor / Membership UX

The shell displays the server-resolved current actor. A workspace member panel shows active membership and relevant role data from authorized backend responses. Actor identity is not accepted from mutation payloads and cannot replace the trusted session boundary.

## 9. Permission UX

The permission panel explains effective capabilities. Unsupported collaboration chapter creation is disabled with an explanation. Frontend capability display is advisory only; backend authorization remains the final authority for direct calls.

## 10. Autosave / Version UX

The editor shows unsaved, saving, saved, failed and conflict states with the current document version. Status changes are exposed through a polite live region. Save requests capture scope, chapter, content, document and base version at dispatch time.

Manual and automatic saves share a single-flight gate. An edit made while a prior save is in flight remains durable, is rebased to the returned version, stays unsaved, and is saved next. Rapid manual saves cannot submit concurrent writes using the same base version.

## 11. Conflict UX

HTTP 409 enters a persistent conflict state and never triggers force overwrite or automatic retry. The dialog shows local and server versions, preserves the local draft, supports adopting the server version, and leaves manual comparison/copy available. A restored draft whose base version differs from the server enters conflict before any write.

The dialog receives initial focus, traps Tab and Shift+Tab, closes with Escape, restores prior focus, and announces the conflict. Conflict, draft and cache records are namespaced by full collaboration scope plus chapter.

## 12. Revision UX

Revision history lists version, actor, time and reason. Detail is loaded on demand and provides a content/document preview. Restore is explicit, explains that it creates a new current revision, and submits the current expected version so concurrent changes still conflict.

## 13. Audit UX

The audit viewer presents recent actor, action, target, scope and timestamp metadata with backend-supported filters and pagination. It does not expose secrets, full prompts, hidden lore, chapter bodies or LOCAL_ONLY payloads.

## 14. ContextSnapshot UX

The snapshot inspector loads summaries first and authorized metadata detail on demand. It exposes snapshot ID, context mode, Context Pack version, token budget, source summary, hash and generation linkage. Raw context, prompts, secrets and LOCAL_ONLY data are excluded by the response schema.

PostgreSQL mode uses the real collaboration runtime, persistent identity/authorization, atomic optimistic concurrency, Revision, Audit and ContextSnapshot storage.
