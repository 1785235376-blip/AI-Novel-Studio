- Compose 已定义 `postgres`、`service`、`frontend`；Ollama 保持 Host Service。
- PostgreSQL 16 容器配置、独立 named volume、健康检查和 54329 主机端口已定义。
- 001/002/003 migrations 均存在，分别覆盖 Canon 核心、Generation Jobs、Document Versions。
- FastAPI、Provider Registry、Ollama Provider、Mock Provider、SSE、Draft Accept、版本历史和 Pending Canon 已实现。
- React/TipTap Writer UI 已通过 TypeScript、Vite production build、Vitest 5/5。
- FastAPI TestClient 已通过完整 Mock 作者流程，但不等于容器/PostgreSQL/真实模型验证。
- 备份、恢复、迁移脚本和开放格式小说资产已存在。

## 3. 缺失依赖与阻塞

1. Docker Desktop / Docker Compose 缺失。按任务要求不自动安装；容器、PostgreSQL、volume 重启持久性均无法执行。
2. Ollama 缺失且没有本地模型。按任务要求不自动安装或下载；真实 Streaming、tokens、latency、显存测试无法执行。
3. Cloud Provider Key 全部缺失。不会申请、创建或写入 Key；真实 Cloud Continue 无法执行。
4. 浏览器 E2E 尚无 Playwright 依赖与浏览器资产。可以在不依赖 Docker的本地 Mock Runtime 上增加测试，但只有实际启动 Backend/Frontend 并驱动浏览器后才可标 REAL VERIFIED。
5. 当前业务 Repository 仍以文件运行时为主；虽然数据库 Schema 已定义，API CRUD/Job 尚未完整切换到 PostgreSQL Repository。即使 Docker 可用，也必须先验证实际数据路径，不能仅因 PostgreSQL 健康就宣称业务数据库已验证。
6. `Dockerfile` 当前只复制 app/config；容器运行需要的 prompt、workflow 和可写目录依赖 Compose mount。需要在构建验证中检查非 Compose 启动行为。
7. README 与早期 deployment report 有过时状态，需要在验证完成后更新，不能作为当前证据。

## 4. 验证目标与顺序

### Phase A — 静态与本机基线

- 校验 Compose 配置、Dockerfile、nginx、环境变量模板和 Secret 隔离。
- 执行 Python tests、TypeScript type-check、Vite build、Vitest。
- 扫描 frontend/dist 与源码，确认不存在 API Key 值或后端 Secret。
- 校验 runtime JSONL 字段白名单和正文/Secret 不落日志。
- 10 万字 Document/Context/Diff 基准测试，使用临时数据，不修改小说资产。

### Phase B — 本地真实 Backend/Frontend

- 使用项目 `.venv` 启动 Uvicorn，使用已构建前端或 Vite preview。
- 验证 `/api/health`、storage、provider、queue 状态。
- 增加 Playwright E2E；若浏览器安装受限，记录 PARTIAL。
- E2E 使用隔离测试 Novel，测试后只删除测试资产，不触碰用户小说。

### Phase C — Docker/PostgreSQL（条件：用户安装并启动 Docker）

- `docker compose config` 后执行 build/up，不操作其他 Compose 项目。
- 验证 frontend/backend/postgres health。
- 检查 001→002→003 migration、tables/indexes/constraints。
- 验证 Novel、Chapter、Document Version、Restore、Canon、Pending Canon、Generation Job。
- 重启 backend/postgres，验证 volume 数据和 RUNNING Job 变 FAILED、不重复执行。
- 只有业务 API 确实读写 PostgreSQL 后才标 Database REAL VERIFIED；仅数据库容器健康只能标 Runtime REAL VERIFIED / Repository PARTIAL。

### Phase D — Ollama（条件：用户安装 Ollama，已有模型）

- 读取 `OLLAMA_BASE_URL`；验证 `/api/providers`、`/api/models`。
- 不下载模型；选择现有模型测试 Continue、Rewrite、Summary。
- 记录 model、input/output tokens、latency、tokens/s、GPU memory before/peak/after。
- 输出 `docs/ollama_runtime_test.md`；无模型继续标 NOT VERIFIED。

### Phase E — Cloud（条件：用户自行配置 Key）

- 仅检测 configured 状态，不向浏览器返回 Key。
- 对配置的 OpenAI-compatible Provider 执行最小 Continue。
- 验证 fallback、usage、latency、日志脱敏；不保存完整 Prompt。

### Phase F — 迁移模拟

- 在临时目标目录验证备份/恢复包、相对路径、配置替换和模型 Manifest。
- 不复制模型 blob，不依赖 `D:/小说/AI-Novel-Studio` 绝对路径。
- Docker 缺失时 SQL restore 标 PARTIAL，但文件资产迁移可 LOCAL VERIFIED。

## 5. Browser E2E 验收用例

打开首页→创建测试小说→创建章节→输入并保存→刷新确认→TipTap 选择文字→Rewrite→Streaming Draft→Diff→Accept→History→Summary/Pending Canon→编辑并 Approve→Export Markdown→Import Preview→确认导入。每一步保存截图/trace 或断言结果；Mock 流程标 MOCK/LOCAL，真实 Ollama 流程才能标 Local Model REAL VERIFIED。

## 6. 风险列表

- **高**：文件 Repository 与 PostgreSQL Schema 并存，数据库健康不代表业务数据已落 PostgreSQL。
- **高**：Docker 缺失使 migrations、volume 重启、容器网络完全不可验证。
- **高**：无 Ollama/模型，核心“真实模型生成”无法验收。
- **中**：进程内 Job executor 不适合多 backend replica；恢复策略必须避免重复生成。
- **中**：大章节可能使 TipTap、Diff 和 Context JSON 产生主线程卡顿或内存峰值。
- **中**：Vite bundle 约 513 KB，需测首屏；本阶段只做小规模 lazy loading，不大重构。
- **中**：Playwright 浏览器下载可能受网络/权限限制。
- **低**：Starlette TestClient 当前有 httpx deprecation warning，不影响现有验证，但需后续升级测试栈。

## 7. 状态判定规则

- REAL VERIFIED：真实进程/容器/数据库/浏览器/模型实际执行并有结果证据。
- LOCAL VERIFIED：本机真实代码执行，但没有目标外部 Runtime。
- MOCK VERIFIED：Mock Provider 或模拟故障验证。
- STATIC VERIFIED：解析、配置或源码扫描。
- PARTIAL：只完成目标的一部分或证据不完整。
- NOT VERIFIED：依赖或环境缺失，未执行。
