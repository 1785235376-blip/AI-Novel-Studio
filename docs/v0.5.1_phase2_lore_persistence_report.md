## Migration

Added `database/migrations/004_lore_foundation.sql`. It only creates `evidence_records`, `lore_proposals`, `lore_proposal_evidence`, indexes, constraints, and the `0.5.1-lore` schema marker. Migrations 001/002/003 were not modified.

The migration enforces source-specific Evidence requirements, enum domains, confidence range, review-state requirements, Proposal/Evidence primary key, foreign keys, and immutable-source uniqueness.

## ORM

Added `app/models/lore.py` with SQLAlchemy 2.x models:

- `EvidenceModel`
- `LoreProposalModel`
- `LoreProposalEvidenceModel`

No existing Character, Location, Timeline, Canon, Secret, or Chapter ORM was changed.

## Repository

`PostgresLoreRepository` now uses the Lore ORM and real transactions. Approval/rejection and Evidence invalidation lock rows with `FOR UPDATE`; invalid transitions roll back. The repository never creates tables and still fails clearly if 004 is absent.

External Lore IDs are preserved inside the serialization boundary; deterministic internal UUIDs are not returned. Proposal payload and Evidence locator are returned without internal mapping metadata.

`RepositoryBundle` and Factory now expose `lore`: File mode returns `FileLoreRepository`, PostgreSQL mode returns `PostgresLoreRepository`, with no fallback.
