## Implemented Boundary

- Added typed `NarrativeChangeProposal`, eight bounded proposal types, and the `PENDING`, `ACCEPTED`, and `REJECTED` lifecycle.
- Added stable semantic fingerprints. Status, timestamps, and backend metadata are excluded.
- Added explicit create/list/get/accept/reject service and API operations with project ownership guards.
- Reused `NarrativeStateService` progress preparation and existing lifecycle transitions.
- Accept performs entity mutation, `NarrativeEvent`, `ChapterNarrativeLink`, and proposal status update in one File snapshot or PostgreSQL transaction.
- Repeated accept is idempotent. Failed or stale accept leaves the proposal `PENDING` and authoritative state unchanged.
- Proposal objects are not read by Narrative Context and no Context Policy source was added.
