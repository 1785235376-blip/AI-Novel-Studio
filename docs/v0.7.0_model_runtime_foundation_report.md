## Implemented Foundation

- `app/model_runtime.py` introduces modality and capability contracts, normalized text request/response/stream events, normalized runtime errors, provider/model descriptors and registries, the legacy-provider compatibility adapter, `TextModelNode`, and `GenerationRuntime`.
- `app/runtime.py` owns the registries/runtime and dynamically registers the currently resolved legacy route provider. Stable provider/model IDs are separate from product-facing display names.
- `app/jobs.py` executes generation through `TextModelNode`, consumes normalized events, preserves existing durable Job/ContextSnapshot persistence and exposes product-safe runtime failures.
- The existing persisted Job is retained as the application-level Generation Job. No duplicate job entity or persistence table was introduced.
- Existing runtime route policy remains authoritative; Phase 1 does not silently select or change vendors.

## Contracts

The normalized text request carries stable provider/model IDs, prompt, optional system instruction and context, validated parameters, optional structured-output schema, non-secret metadata and job reference. The normalized response carries text, finish reason, stable IDs, optional usage/reference metadata and latency. Streaming uses `generation.started`, `generation.delta`, and `generation.completed`; provider exceptions are mapped to provider-neutral errors.

Capability validation occurs before provider execution for unknown/unavailable providers, unknown/disabled models, non-text modality, unsupported streaming and unsupported structured output. Temperature and token limits are validated by the normalized parameter contract.

## Secret and Observability Strategy

- Credentials are not fields of runtime request/response, Job, registry descriptors or stream events.
- Provider exceptions are replaced by safe Chinese product messages; raw provider error text is not serialized to authors.
- Runtime logs record generation/job identity, provider/model IDs, status and normalized failure category, not credentials or raw provider exception objects.
- No new credential persistence was created. Existing environment-based provider configuration remains the development contract until a separately authorized secure configuration phase.
