## Current Phase 1 Baseline

The inspected production path is:

```text
Author UI
  -> trusted generation API / JobManager
  -> scoped ContextService and prompt assembly
  -> GenerationRuntime
  -> builtin.text_model v1
  -> ProviderRegistry / ModelRegistry
  -> normalized TextProvider
  -> provider adapter
```

`TextModelNode` depends only on the normalized provider protocol. Provider adapters do not query Novel repositories. The existing Job persists actor/scope, snapshot linkage and base chapter version, while accept/reject remains version-aware and creates normal revision history. Route-local provider injection compatibility is present and must remain frozen.

The repository already has lightweight HTTP implementations and configuration slots for Ollama and several OpenAI-compatible services, including `DEEPSEEK_API_KEY`, but the legacy compatible adapter is non-streaming, collapses errors, and is not yet sufficient evidence of a production real-provider integration.

## Candidate Categories

The decision evaluates four architectural categories and representative targets:

- Direct vendor SDK: OpenAI, Anthropic or Gemini official SDK.
- Direct vendor-native HTTP: native REST/SSE contract for one vendor.
- Generic OpenAI-compatible HTTP: remote OpenAI-compatible endpoints; initial target DeepSeek.
- Local provider: OpenAI-compatible local endpoint or native Ollama HTTP.

No new provider SDK is required for the selected approach. The existing `httpx` dependency can provide bounded async/sync HTTP streaming and explicit connection lifecycle in Phase 2B.

### Score rationale

- Official SDKs offer strong typing, streaming helpers and mature documentation, but add dependency churn and encourage vendor-specific types/errors to leak into the runtime. They are valuable future native adapters, not the best first portability proof.
- Anthropic and Gemini have capable native protocols, but forcing them into an OpenAI-shaped contract would lose native semantics. They should receive native adapters only when their capabilities are explicitly authorized.
- Generic OpenAI-compatible HTTP fits the existing normalized request, preserves full control over SSE parsing, abort, timeout and error mapping, and works with multiple remote/local/self-hosted runtimes. Compatibility quirks must be contained inside per-provider configuration/adapter tests.
- DeepSeek is selected as the first concrete remote validation target because the repository already authorizes/configures its provider identity and credential environment slot, it presents the chosen compatible contract, and it validates a real non-OpenAI vendor without installing a vendor SDK.
- Ollama remains the best secondary local strategy. It already has a native HTTP foothold and proves local/offline providers do not require Novel application changes, but a local runtime/model is not guaranteed to be installed and therefore is less deterministic as the first external production baseline.

## Provider Contract Fit

```text
CURRENT PROVIDER CONTRACT FIT = EXTENSION REQUIRED
TEXT MODEL NODE PROVIDER NEUTRALITY = PASS
MAJOR REDESIGN REQUIRED = NO
```

Already sufficient:

- stable provider/model identity and descriptors;
- text request/response DTOs;
- optional usage, latency and safe provider reference;
- normalized start/delta/completed events;
- registry availability and model capability checks;
- structured-output capability gate;
- route-local provider injection compatibility.

Generic extensions required before real execution:

1. Add `AUTHENTICATION_FAILED`, `RATE_LIMITED`, and `TIMEOUT` to `RuntimeErrorCode`.
2. Add an adapter-visible cancellation signal/token or execution context; do not place vendor clients in `TextModelNode`.
3. Require real adapters to emit terminal `generation.failed`/`generation.cancelled` semantics or raise normalized errors that the runtime converts once.
4. Preserve provider-reported usage/finish reason on streaming completion instead of estimating it when provider metadata is available.
5. Define bounded connect, first-response and overall generation timeouts.
6. Define non-secret provider configuration validation and safe health/status behavior.

These are generic runtime requirements. Vendor request enums, SDK exception classes and vendor-only convenience fields do not belong in the core contract.

## Streaming Strategy

DeepSeek/OpenAI-compatible streaming should use HTTP SSE over one explicitly owned `httpx` streaming response:

```text
request accepted -> generation.started
SSE content delta -> generation.delta
provider terminal chunk -> generation.completed(response, usage, finish_reason)
normalized transport/provider error -> generation.failed / ModelRuntimeError
cancel signal + response close -> generation.cancelled / CANCELLED
```

The parser must tolerate legal frame boundaries, ignore heartbeat/comment frames, reject malformed terminal data safely, and never expose raw response bodies containing sensitive diagnostics to the author UI.

## Cancellation Strategy

Current cancellation only marks the Job and discards later chunks; it does not abort an in-flight network read. Phase 2B must propagate cancellation:

```text
Frontend cancel
  -> generation cancel endpoint
  -> Job cancellation event
  -> Text provider execution context
  -> close/abort owned HTTP stream
  -> normalized CANCELLED terminal state
```

Provider-side cancellation APIs are optional. Transport abort stops local resource use; the provider may still bill work already accepted. If an abort race returns a final chunk, the cancelled Job must discard it and must never become COMPLETED. No detached background stream may continue after terminal cleanup.

## Model Discovery and Default Policy

```text
MODEL DISCOVERY = HYBRID
```

- Startup uses statically configured, reviewed model IDs so author workflows are deterministic and work when model-list endpoints are slow/unavailable.
- An optional provider model-list refresh may enrich availability/metadata but must not silently enable models or become required for generation.
- Registry identity remains `(provider_id, internal model_id)`; display names are product-facing metadata.
- Resolution is `explicit requested model -> explicitly configured default for that provider/purpose -> MODEL_NOT_FOUND/MODEL_DISABLED`.
- No automatic switch to another paid provider is allowed. Fallback requires explicit route policy and visible configuration.

## Credential and Secret Strategy

### Ownership

For Phase 2B the credential is **machine/process-level provider configuration**, not Workspace, Novel, user or GenerationJob data. It is loaded by the backend process from `DEEPSEEK_API_KEY`. It is never accepted in generation request bodies.

### Options considered

| Option | Phase 2B decision | Reason |
|---|---|---|
| Environment-only | Selected temporarily | No schema, already supported, keeps key server-side; deployment must inject it securely. |
| Encrypted local config | Deferred | Requires key lifecycle and desktop ownership decisions. Encryption beside its key is not meaningful protection. |
| Windows Credential Manager | Preferred future workstation option | Good OS-managed boundary, but needs desktop/service account and headless behavior decisions. |
| DPAPI-backed storage | Candidate future implementation | Strong machine/user binding; backup, account change and service execution semantics need product design. |
| Database encrypted field | Rejected for Phase 2B | Adds schema, key management and File/PostgreSQL parity without helping the first runtime proof. |
| Desktop shell secure storage | Deferred | Desktop shell/EXE is outside V0.7.0 Phase 2B. |

```text
SECRET STORAGE PHASE 2 = ENVIRONMENT / PROCESS SESSION ONLY
PERSISTENT SECRET STORAGE = NO / DEFERRED
PERSISTENT SECRET STORAGE PRODUCTIZED = NO
```

Minimum invariant: secret is never returned to frontend, localStorage, URL, logs, audit, Job, screenshots, test snapshots, error serialization or retained process manifests. Tests must use sentinel secrets and inspect safe errors/log output. The real key must not be committed or written to the report.

## Retry and Timeout Policy

- Default automatic retry count for generation is zero in the first real-provider closure. This avoids duplicate paid generations and ambiguous partial streams.
- Authentication, invalid request, unknown model and capability errors are never retried.
- Rate limit, timeout and temporary unavailable may be exposed as `retryable=true`; a later explicit policy may perform at most one pre-first-token retry with jitter and the same idempotency/correlation reference where supported.
- Never retry after any author-visible delta unless the protocol can prove safe resume; Phase 2B should fail the draft while preserving the manuscript.
- Proposed defaults: connect 10 s, first response 30 s, overall generation 120 s, all configurable within bounded positive ranges.

## Error Normalization

| Condition | Runtime code | Chinese author message class | Retry |
|---|---|---|---|
| Missing/malformed configuration | `INVALID_CONFIGURATION` | 模型未配置 | No |
| HTTP 401/403 credential rejection | `AUTHENTICATION_FAILED` | 模型凭据无效 | No |
| HTTP 404/model error | `MODEL_NOT_FOUND` | 找不到所选模型 | No |
| HTTP 400/422 request error | `INVALID_REQUEST` | 生成请求无效 | No |
| HTTP 429 | `RATE_LIMITED` | 请求过于频繁 | Maybe/manual |
| Connect/read/overall timeout | `TIMEOUT` | 生成超时 | Maybe/manual |
| HTTP 5xx/network unavailable | `PROVIDER_UNAVAILABLE` | 模型暂时不可用 | Maybe/manual |
| Invalid SSE/response payload | `GENERATION_FAILED` | 生成失败 | No by default |
| Local abort/cancel | `CANCELLED` | 已停止生成 | No |

Raw HTTP bodies, exception classes, stack traces, internal IDs and credential-bearing headers remain internal and redacted.

## Remote Data Boundary and Context Minimization

```text
REMOTE MODEL DATA BOUNDARY = EXTERNAL
```

For a remote provider, the final assembled prompt and approved cloud context leave the local machine. Candidate data includes selected text/current chapter excerpt and only the Story Database, character memory, worldbuilding and continuity facts selected by current context policy. The entire Workspace or Novel must not be sent by default.

Existing `cloud_safe_context`/locality policy is the starting boundary, not sufficient proof by itself. Phase 2B tests must demonstrate `LOCAL_ONLY` exclusions, workspace/novel/actor/lore isolation and snapshot evidence for exactly the generation context. Live smoke uses a synthetic non-sensitive prompt with bounded output; no real manuscript is used for connectivity verification.

## Local Provider and Desktop Compatibility

The choice does not change Novel application services. A future local OpenAI-compatible adapter can reuse the generic transport with a distinct provider ID and no credential, while native Ollama remains a separate adapter where its protocol is more faithful. Offline/local providers therefore do not require rewriting `TextModelNode` or Job/revision logic.

For a future desktop executable, provider descriptors, model defaults, credential lookup and health checks can be composed at backend startup. Environment-only is acceptable for Phase 2B verification but not the final desktop UX. A later desktop decision should prefer Windows Credential Manager or DPAPI-backed storage with explicit export/backup/account semantics.

## Phase 2B Test Strategy

Layer 1 — reusable provider contract:

- registration/model resolution, normal and streaming generation;
- cancellation before request and during stream;
- invalid credential/model/request, rate-limit, timeout and 5xx mapping;
- usage/finish reason/provider reference mapping;
- secret redaction from errors, logs, Job/audit/API;
- malformed/fragmented SSE and cleanup of response resources.

Layer 2 — controlled live smoke:

- real DeepSeek HTTPS request using environment credential;
- synthetic non-sensitive prompt, one bounded request, low output token limit;
- verify at least one delta, completion, selected model and usage when supplied;
- separate bounded cancellation smoke if reliably supported;
- never print key, authorization header or raw sensitive response.

Layer 3 — real author journey:

```text
Novel -> Chapter -> AI Draft -> DeepSeek -> Result -> Diff
-> Accept or Reject -> version-aware Revision
```

This uses production frontend/backend, real PostgreSQL and real Chromium. It must also cover no manuscript loss, cancellation, normalized failure UI, trusted ActorContext and context isolation. Only after all three layers pass may `REAL EXTERNAL PROVIDER = VERIFIED` be claimed.

## Risks

- “OpenAI-compatible” endpoints vary in SSE termination, structured output, model listing and error payloads. Contract tests and provider configuration must isolate these differences.
- Environment variables are operationally safe enough for controlled integration but are not a product credential-management UX.
- Current cancellation is result-discard only; network abort is a release blocker for Phase 2B.
- Existing legacy error mapping collapses all provider failures; normalized categories are a release blocker.
- Remote generation crosses an external privacy boundary; cloud context tests and explicit user/product disclosure are required before general use.
- Real tests may incur cost and rate limits; request/token counts must remain bounded.

## Secondary / Fallback Strategy

```text
SECONDARY STRATEGY = OLLAMA NATIVE HTTP OR LOCAL OPENAI-COMPATIBLE ENDPOINT
IMPLEMENT NOW = NO
```

This validates that the first adapter does not own runtime contracts. A second paid remote provider is not an automatic fallback. Any future fallback remains explicit, capability-checked and visible; silent cross-provider paid fallback is prohibited.
