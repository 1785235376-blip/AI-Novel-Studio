## Known issue

### Novel title/list cache is stale immediately after creation

- Step: Create Novel
- Page: Writer Workspace header
- API: `POST /api/novels` succeeds and returns the correct novel
- Database: the novel exists with the correct slug and title
- Actual UI: workspace and context switch to the new novel, but the header derives its title from a stale novels query and renders no title
- Cause: the create action sets the selected novel ID without invalidating or updating the novels query cache
- Treatment in this phase: recorded only; no frontend/core business change was made

Because the requested acceptance explicitly says the created novel must appear in the list, the overall Phase 4 status remains **PARTIAL**, even though the rest of the real browser journey completed and the automated E2E test passes using context/API/database as the creation assertion.
